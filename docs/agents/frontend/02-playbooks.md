## 7. 前端构建产物治理（Vue 登录/管理端）· 索引

> **多人协作下的完整口径（为何不用 hash、固定名与 `version.txt`、冲突动作、日常 vs 发版）以 §8 为唯一正式说明。** 本节仅作快速定位。

- **产物目录**：`frontend-vue` 构建输出到 `frontend/vue-auth-assets/`，供 `frontend/login.html`、`frontend/admin.html` 加载；目录内为 **构建产物**，不是业务源码。
- **实现侧要点（冻结）**：产物为 **固定文件名**；构建 **前** 会清空 `frontend/vue-auth-assets/`；构建后写入 **`version.txt`**；入口通过 **`?v=...`（query version）** 破缓存。
- **冲突与职责**：凡 `vue-auth-assets` 在 Git 或其它环节冲突，**不手工 merge 产物**，**先合并 `frontend-vue` 源码再统一重新构建**。细则见 **§8. frontend-vue 构建产物协作规则**。

## 8. frontend-vue 构建产物协作规则

> **任务号**：`FE-20260326-01`  
> **性质**：本条为 **当前阶段正式的多人协作规则**，适用于多名研发同时改动 `frontend-vue` 相关功能、并共同触碰或生成 `frontend/vue-auth-assets/` 的场景；与「仅改业务逻辑」无关的实现冻结已由 owner 确认，**本阶段协作重点是把产物冲突与提交节奏统一在文档层**，避免各人凭经验各行其是。

### 8.1 为什么不再采用带 hash 的文件名产物

- **目录与审阅成本**：每次构建若输出新 hash 文件名，历史上清理不彻底时，`vue-auth-assets` 易 **无限堆积** 旧文件，diff 噪音大、仓库臃肿。
- **合并不可行**：多人并行改 `frontend-vue` 时，产物多为 **二进制/单行压缩**，Git 冲突下 **几乎无法做有意义的语义化 merge**；手工挑文件合并极易得到 **与当前源码不一致** 的静态资源组合。
- **结论**：弃用「按次构建生成不同物理文件名」的堆叠方式，改为 **固定物理文件名 + 版本元数据**，把「哪一版正确」收敛为 **一次构建、一套产物**。

### 8.2 为什么采用固定文件名 + `version.txt` + `?v=...`

- **固定文件名**：同一批入口始终引用同一组路径（如 `login.js`、`admin.js` 等），避免入口 HTML 与资源文件名连锁变动；构建 **前清空** `vue-auth-assets`，保证目录内只有 **当前构建对应** 的文件集，无历史 hash 残留。
- **`version.txt`**：由构建写入，表征 **本次构建的版本令牌**（与时间或构建标识一致即可），供运行时读取；**单一事实来源**，避免 HTML 里写死版本号、与真实产物脱节。
- **Query version（`?v=...`）**：浏览器会强缓存同名 URL；入口在加载脚本/样式时拼接 `?v=<version.txt 内容>`，可在 **不改动物理文件名** 的前提下 **强制拉取新资源**，兼顾协作简单与缓存策略。

### 8.3 `frontend/vue-auth-assets/` 冲突时的标准处理动作（硬规则）

当 Git merge/rebase 或其它协作环节出现 **`frontend/vue-auth-assets/` 下文件冲突** 时：

1. **不对产物目录做手工 merge**（不逐文件解决冲突、不「保留两边的部分 js/css」拼凑）。
2. **先完成源码侧合并**：将 `frontend-vue/src/...`、`frontend-vue` 配置与入口约定等与功能相关的 **源码与配置** 按正常流程合并完毕。
3. **由具备上下文的一方或 CI/负责人统一执行一次 `frontend-vue` 构建**，使构建脚本 **清空旧产物** 并生成 **与合并后源码唯一对应** 的一套 `vue-auth-assets`。
4. **将新生成的产物作为整包提交**（或按团队约定的发版分支策略提交），以该次构建结果为权威。

**原理**：重新构建会 **清掉旧文件并重写 `version.txt`**，产物树始终是 **单构建、单真相**；手工 merge 产物无法保证与任意组合的源码一致，故 **禁止**。

### 8.4 日常开发与收口 / 发版前的职责区分

- **日常开发**：优先且主要修改 **`frontend-vue/src/...`**（及与本模块相关的配置）；本地可频繁构建自测，**不必**每次小步都提交 `vue-auth-assets`（以团队节奏为准），但需知 **运行时以已提交的产物为准** 的另一路径应与负责人对齐。
- **收口 / 发版前**：在功能合并稳定后，**统一执行构建**，更新 **`frontend/vue-auth-assets/`** 与 **`version.txt`**，并 **随发版或集成分支一并提交**，确保 `login.html` / `admin.html` 引用的静态资源与线上/集成分支的 `frontend-vue` 源码 **一致**。

**本节与 §7 索引配套使用**：agent 与研发在处理 `vue-auth-assets` 争议时，**默认引用本节**，不再在聊天里重复解释「能不能手工合并产物」。

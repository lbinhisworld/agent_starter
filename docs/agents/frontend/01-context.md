# Frontend Agent · 背景与上下文

> 相对稳定的全局背景与边界；与 `00-core.md` 配合阅读。任务状态以 `03-active-tasks.md` 为准。

## 1. 项目背景

- 当前需重点关注两个前端项目：
  - `frontend/`：主业务前端，尤其是 `ProblemDetail` 主链路与核心业务交互。
  - `frontend-vue/`：Vue 工程，侧重登录、管理端及后续可迁移能力。
- 系统核心目标（阶段口径）：优先打通 `ProblemDetail` 闭环。
- 当前前端现状：
  - `main.js` 体量较大，历史上前端承载过多业务规则。
  - 任务推进、消息流、回退裁决需逐步后移到后端。
- 工作策略：前端继续交付页面，**不新增本地业务真相源**。

## 2. 本周 / 阶段目标（摘要）

- `ProblemDetail` 页面以后端接口为主。
- 消息时间线统一从后端读取；新增消息以追加为主，避免整段覆盖主路径。
- 确认、修订、回退通过后端动作接口完成。
- 页面刷新后可恢复 `case`、`tasks`、`messages`。
- 案例详情路由须携带后端标准 `caseId`（不单独依赖 `sessionStorage + createdAt` 作为详情主键）。

## 3. 冻结边界

### 前端负责

- 页面展示、消息渲染、面板切换、输入与草稿态、调用接口后刷新 UI。

### 前端不再负责

- 定义任务推进规则、回退规则、确认后阶段跳转规则。
- 新增本地 `localStorage` 业务真相。

## 4. 任务清单（按优先级摘要）

详细 P0/P1/P2 清单与接口替换步骤见 **`02-playbooks.md`**「本周任务清单」；此处仅保留方向性摘要。

- **P0**：鉴权调用路径收口；`ProblemDetail` 接口调用点梳理；消息追加与动作接口主路径；`caseId` 路由。
- **P1**：消息渲染模型统一；减少对「整段覆盖消息」主路径依赖；清点仍依赖本地裁决的逻辑并标风险。
- **P2**：`ProblemDetail` 内 loading/错误/空态收口；联调记录。

## 5. 需要业务人员确认的内容

- 哪些结果卡必须在当前阶段可展示。
- 哪些 `task` 必须可跑通。
- 回退后页面预期表现。

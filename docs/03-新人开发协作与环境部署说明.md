# Smart CTO 开发协作与环境部署说明

## 1. 项目概览

当前仓库是一个前后端一体仓，核心模块如下：

| 模块 | 作用 | 说明 |
| ---- | ---- | ---- |
| `frontend/` | 主业务前端 | 承载数字化问题跟进主流程、工作区、聊天区与页面状态编排 |
| `frontend-vue/` | Vue 登录/管理端 | 负责登录页、管理员后台、模型配置页、首页 Vue 壳；构建产物输出到 `frontend/` |
| `backend/` | 后端服务 | 提供鉴权、问题案例、AI 代理、配置管理与数据库访问能力 |
| `docs/` | 文档目录 | 放置架构、部署、设计、知识卡与协作说明 |
| `docs/agents/` | 多角色协作文档 | 用于沉淀架构、前端、后端、业务产品的协作边界与任务台账 |

一句话理解：

- `frontend/` 负责业务页面
- `frontend-vue/` 负责登录和管理体系
- `backend/` 负责接口、鉴权、数据库和 AI 代理

## 2. 开发规范

### 2.1 基本原则

项目当前遵循以下固定规则：

- 安全优先：不要执行有破坏性的命令，不要泄露密钥、密码、证书。
- 最小化变更：只改本次任务相关内容，不顺手重构、不顺手修别的问题。
- 理解优先：改代码前先读上下文，先理解现有设计意图，再动手。
- 代码英文、注释中文、提交信息中文。

### 2.2 文档同步规则

这个项目要求“代码改完，文档也要同步”。

至少要记住这条链路：

1. 改完代码后，检查目标文件头注释是否需要更新
2. 检查所在目录的 `AGENTS.md` 是否需要更新
3. 如果影响到顶层结构或模块边界，再更新根目录 `AGENTS.md`

典型触发场景：

- 新增/删除/重命名文件
- 调整模块职责
- 修改前后端接口边界
- 新增顶层模块

### 2.3 模块边界

- 不要混改前后端无关逻辑。
- `frontend-vue/` 的源码改动后，必须重新构建，并把生成到 `frontend/` 的产物一起提交。
- 后端 AI Key、JWT Secret 等敏感信息只放后端环境或数据库配置中，不能写入前端源码或构建配置。

### 2.4 提交规范

提交信息统一使用中文，格式如下：

```text
<type>(<scope>): 中文摘要
```

可用类型：

- `feat`
- `fix`
- `refactor`
- `test`
- `docs`
- `chore`

常用 scope：

- `backend`
- `frontend`
- `frontend-vue`
- `problem-detail`
- `agents`

示例：

```text
fix(frontend): 修复问题详情任务切换状态显示
feat(backend): 增加用户模型配置接口
docs(agents): 同步本地启动与协作说明
```

提交粒度要求：

- 一次 commit 只做一个主题
- 前端和后端不要混在同一个 commit
- 文档可跟随责任侧一起提交；纯文档收口可单独提交

## 3. 分支管理

### 3.1 当前仓库现状

当前仓库可见的长期分支主要有：

- `main-remote`
- `main-remote-review-0330`
- 若干 `backup/*` 备份分支

新人开发时，不建议直接在长期分支上开发。

### 3.2 建议的日常开发方式

建议每个需求、缺陷或小专题都单独开分支，命名尽量清晰：

```bash
feature/xxx
fix/xxx
chore/xxx
docs/xxx
```

如果团队本阶段明确指定了集成基线分支，则从指定分支拉个人分支；如果没有额外通知，先和当前负责人确认以哪个长期分支为基线。

推荐流程：

1. 先拉最新基线分支
2. 基于基线创建个人功能分支
3. 在个人分支开发、自测、提交
4. 提交 review
5. 通过后再合入集成分支

### 3.3 分支协作注意事项

- 不要直接在别人正在使用的分支上提交。
- 不要把前后端多个独立主题揉到一个分支里。
- 遇到 `frontend/vue-auth-assets/` 冲突时，不要手工拼产物，应该先合并 `frontend-vue/` 源码后重新构建。
- 合并前先同步最新基线，减少大范围冲突。

## 4. 本地开发环境

### 4.1 基础依赖

建议提前准备：

- Node.js
- npm
- MySQL 或 MariaDB
- Git

生产部署文档当前使用的 Node 版本是 `24.14.0`，本地开发也建议尽量保持一致。

### 4.2 后端本地环境

后端本地开发最重要的约定只有两条：

1. 先检查 `backend/.env`
2. 不要手动拆步启动，统一走脚本

#### 启动前先检查

- `backend/.env` 文件存在
- `DATABASE_URL` 非空
- 若仓库新增环境项，及时对照 `.env.example` 补齐

#### Windows 启动方式

在仓库根目录执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File backend/scripts/start-local-backend.ps1
```

查看状态：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File backend/scripts/status-local-backend.ps1
```

停止服务：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File backend/scripts/stop-local-backend.ps1
```

#### macOS / Linux 启动方式

```bash
bash backend/scripts/start-local-backend.sh
```

可选跳过项仅用于排障，不建议日常使用：

```bash
bash backend/scripts/start-local-backend.sh --skip-build --skip-db-push
```

#### 为什么必须走脚本

启动脚本会自动串联以下动作：

- 读取并校验 `backend/.env`
- 检查数据库可达性
- 执行 `prisma db push`
- 执行 `npm run build`
- 启动服务
- 轮询 `/health`
- 处理默认管理员等运行时初始化

所以不要为了省事改成手动 `build`、`db push`、`node dist/...` 的拆步方式。

### 4.3 前端本地环境

#### `frontend/`

主业务前端是静态站点，最简单的启动方式：

```bash
cd frontend
npx serve .
```

然后打开终端提示的本地地址。

前端有两种模式：

- `local`：本地存储 + 直连模型
- `online`：走后端接口 + 数据库存储

本地个人调试通常优先用 `local`；团队联调、账号体系、共享案例则使用 `online`。

#### `frontend-vue/`

本地开发：

```bash
cd frontend-vue
npm install
npm run dev
```

如果改了 `frontend-vue/` 源码，收口时必须执行：

```bash
cd frontend-vue
npm run build
```

构建后会同步更新：

- `frontend/vue-auth-assets/`
- `frontend/login.html`
- `frontend/admin.html`
- `frontend/home.html`
- `frontend/model-config.html`

如果这些产物没有一起提交或部署，线上/联调环境不会生效。

### 4.4 数据与密钥约束

- 不提交真实 API Key、数据库密码、JWT Secret。
- `config.local.js` 只能放本地个人配置，不进入仓库。
- 生产环境的 AI Key 由后端接口写入配置，不写在前端。

## 5. 本地联调建议流程

新人第一次接手，建议按下面顺序跑通：

1. 拉取最新代码
2. 检查 `backend/.env`
3. 启动本地数据库
4. 执行后端启动脚本并确认 `/health` 正常
5. 启动 `frontend/` 或 `frontend-vue/`
6. 根据当前任务决定使用 `local` 还是 `online`
7. 进入页面验证登录、列表、详情、接口调用是否正常

如果是联调场景，优先验证：

- 登录是否正常
- 案例列表是否能加载
- 问题详情是否能读取
- AI 相关接口是否可用
- 管理员账号是否可登录

## 6. 环境部署

当前项目的标准部署思路是：

- Linux 虚拟机
- Nginx 反向代理
- PM2 托管后端
- MySQL/MariaDB 存储业务数据

### 6.1 推荐部署环境

- 系统：Ubuntu 22.04 / 24.04
- Node.js：`24.14.0`
- Web：`nginx`
- 进程管理：`pm2`
- 数据库：`MySQL 8` 或 `MariaDB`

### 6.2 服务器目录建议

```text
/srv/do1_smart_cto/
/srv/do1_smart_cto/frontend/
/srv/do1_smart_cto/backend/
```

### 6.3 后端部署流程

#### 1. 准备数据库

创建库和账号：

```sql
CREATE DATABASE do1_smart_cto CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'smart_cto_app'@'127.0.0.1' IDENTIFIED BY '<strong-password>';
GRANT ALL PRIVILEGES ON do1_smart_cto.* TO 'smart_cto_app'@'127.0.0.1';
FLUSH PRIVILEGES;
```

#### 2. 配置后端环境变量

`backend/.env` 至少要有：

```env
NODE_ENV=production
HOST=0.0.0.0
PORT=3000
DATABASE_URL=mysql://smart_cto_app:<strong-password>@127.0.0.1:3306/do1_smart_cto
JWT_SECRET=<your-secret>
```

#### 3. 安装、建表、构建

```bash
cd /srv/do1_smart_cto/backend
npm install
npm run prisma:generate
npx prisma db push
npm run build
```

#### 4. 使用 PM2 启动

```bash
cd /srv/do1_smart_cto/backend
pm2 start npm --name smart-cto-backend -- start
pm2 save
pm2 startup
```

#### 5. 健康检查

```bash
curl http://127.0.0.1:3000/health
curl http://127.0.0.1:3000/api/ai/config
```

### 6.4 AI 配置部署原则

生产环境不要把模型 Key 写在前端。

正确做法是：

- 先启动后端
- 再通过后端接口写入 AI 配置

例如：

```bash
curl -X PUT http://127.0.0.1:3000/api/ai/config \
  -H "Content-Type: application/json" \
  -d '{
    "apiKey": "YOUR_REAL_KEY",
    "apiUrl": "https://api.deepseek.com/v1/chat/completions",
    "model": "deepseek-chat"
  }'
```

### 6.5 前端部署流程

前端部署重点是两件事：

1. 产物准备正确
2. `MODE` 和 `BACKEND_API_URL` 配对正确

当前仓库里的前端部署要分两部分理解：

- `frontend/` 主站本身以静态资源为主
- `frontend-vue/` 负责编译登录/管理/首页等 Vue 页面，并把产物写回 `frontend/`

如果改动了 `frontend-vue/`，先在构建机上执行：

```bash
cd /srv/do1_smart_cto/frontend-vue
npm install
npm run build
```

然后部署 `frontend/` 目录中的静态资源；若当前环境存在 `frontend/dist`，则以构建产物为准，否则按现有静态文件方式部署 `index.html`、`home.html`、`login.html`、`admin.html`、`model-config.html`、`js/`、`styles.css`、`vue-auth-assets/` 等文件。

运行时需要保证前端为在线模式，例如：

```javascript
window.APP_CONFIG = window.APP_CONFIG || {};
window.APP_CONFIG.MODE = 'online';
window.APP_CONFIG.BACKEND_API_URL = 'https://你的域名/api';
```

### 6.6 Nginx 反向代理要点

Nginx 负责两件事：

- 前端静态资源对外访问
- `/api` 请求转发到本机后端 `3000` 端口

核心示意：

```nginx
server {
    listen 80;
    server_name YOUR_DOMAIN_OR_IP;

    root /srv/do1_smart_cto/frontend/dist;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass http://127.0.0.1:3000/api/;
    }

    location /health {
        proxy_pass http://127.0.0.1:3000/health;
    }
}
```

### 6.7 初次上线后必须确认

- 后端健康检查正常
- 前端页面能打开
- 登录页可用
- 默认管理员 `root / root` 可登录
- 首次登录后立即修改 root 密码
- 案例创建、详情读取、AI 功能至少各走通一次

## 7. 常见坑位

- 只改了 `frontend-vue/` 源码，但忘了重新构建并提交 `frontend/` 产物。
- 后端没有检查 `.env`，导致数据库连不上。
- 手动拆步启动后端，漏掉初始化流程。
- 把前端和后端改动混在一个 commit。
- 把敏感配置提交进仓库。
- 联调时前端 `MODE` 与 `BACKEND_API_URL` 配错。
- 生产环境把 AI Key 写进前端配置，这是明确禁止的。

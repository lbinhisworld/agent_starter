# Smart CTO 部署手册

本文档供运维在服务器上部署 Smart CTO 的前端、后端与数据库，使环境可对外提供服务。

## 1. 推荐虚拟机规格

- **系统**：Ubuntu 22.04 LTS 或 Ubuntu 24.04 LTS
- **CPU**：2 vCPU 及以上
- **内存**：4 GB 及以上
- **磁盘**：40 GB 及以上
- **网络**：需可访问外网（用于 npm 安装及大模型 API）

## 2. 需在机器上安装的软件

- `git`、`curl`、`unzip`、`build-essential`
- `nginx`
- `MariaDB` 或 `MySQL`（二选一）
- `nvm` + `Node.js 24.14.0`
- `pm2`

Ubuntu 下建议安装命令：

```bash
sudo apt update
sudo apt install -y git curl unzip build-essential nginx mariadb-server
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.3/install.sh | bash
source ~/.bashrc
nvm install 24.14.0
nvm use 24.14.0
npm install -g pm2
```

若使用 MySQL 而非 MariaDB：

```bash
sudo apt install -y mysql-server
```

安装后建议校验版本：

```bash
node -v
npm -v
pm2 -v
mysql --version   # 或 mariadb --version
nginx -v
```

## 3. 网络与访问要求

- 开放入站端口：`80`、`443`
- 建议后端只监听 `127.0.0.1:3000`，通过 Nginx 反向代理对外暴露
- 若有域名，建议配置 SSL 证书（见下文）

## 4. 服务器上的项目目录

建议目录结构：

```text
/srv/do1_smart_cto/
/srv/do1_smart_cto/frontend/
/srv/do1_smart_cto/backend/
```

创建并拉取代码示例：

```bash
sudo mkdir -p /srv/do1_smart_cto
sudo chown -R $USER:$USER /srv/do1_smart_cto
cd /srv/do1_smart_cto
git clone <你的仓库地址> .
```

若通过压缩包上传，则解压到 `/srv/do1_smart_cto` 即可。

## 5. 数据库准备（MySQL / MariaDB）

### 5.1 安全初始化（仅首次安装 MySQL/MariaDB 时）

若刚安装 MySQL：

```bash
sudo mysql_secure_installation
```

按提示设置 root 密码、移除匿名用户、禁止远程 root 登录等。

### 5.2 创建库与账号

登录数据库：

```bash
sudo mysql -u root -p
```

执行（请将 `<strong-password>` 替换为强密码）：

```sql
CREATE DATABASE do1_smart_cto CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'smart_cto_app'@'127.0.0.1' IDENTIFIED BY '<strong-password>';
GRANT ALL PRIVILEGES ON do1_smart_cto.* TO 'smart_cto_app'@'127.0.0.1';
FLUSH PRIVILEGES;
EXIT;
```

验证连接：

```bash
mysql -u smart_cto_app -p -h 127.0.0.1 do1_smart_cto -e "SELECT 1;"
```

## 6. 后端部署

### 6.1 环境变量

在 `backend/` 目录创建 `.env` 文件（可参考 `backend/.env.example` 若存在）。

**必填项：**

- `NODE_ENV=production`
- `HOST=0.0.0.0`（生产建议显式设置，以便本机可被 Nginx 访问）
- `PORT=3000`
- `DATABASE_URL=mysql://smart_cto_app:<strong-password>@127.0.0.1:3306/do1_smart_cto`

**选填（推荐生产环境配置）：**

- `JWT_SECRET`：JWT 签名密钥（不设则使用代码内默认值，生产建议自定义）
- `JWT_EXPIRES_IN`：JWT 过期时间，默认 `2h`

示例 `.env`：

```env
NODE_ENV=production
HOST=0.0.0.0
PORT=3000
DATABASE_URL=mysql://smart_cto_app:你的密码@127.0.0.1:3306/do1_smart_cto
JWT_SECRET=你的随机长字符串
```

### 6.2 安装依赖与构建

```bash
cd /srv/do1_smart_cto/backend
npm install
npm run prisma:generate
```

**数据库表结构** 任选其一：

- **方式 A（简单、无迁移文件）**：`npx prisma db push`
- **方式 B（有迁移脚本时）**：`npx prisma migrate deploy`

然后构建：

```bash
npm run build
```

### 6.3 使用 PM2 启动

```bash
cd /srv/do1_smart_cto/backend
pm2 start npm --name smart-cto-backend -- start
pm2 save
pm2 startup
```

### 6.4 健康检查

```bash
curl http://127.0.0.1:3000/health
curl http://127.0.0.1:3000/api/ai/config
```

预期 `/health` 返回中包含：

- `ok: true`
- `service: smart-cto-backend`

可选：`curl http://127.0.0.1:3000/api-docs` 或 `openapi.json` 确认接口文档可访问。

## 7. 后端 AI 配置（勿把 Key 放前端）

AI 配置存于后端 `AppSetting` 表，由接口读写。**生产环境不要在前端或前端构建中写入大模型 API Key。**

后端启动后，通过接口写入 DeepSeek 配置（将 `YOUR_REAL_KEY` 换成真实 Key）：

```bash
curl -X PUT http://127.0.0.1:3000/api/ai/config \
  -H "Content-Type: application/json" \
  -d '{
    "apiKey": "YOUR_REAL_KEY",
    "apiUrl": "https://api.deepseek.com/v1/chat/completions",
    "model": "deepseek-chat"
  }'
```

## 8. 管理员账号（初次部署必读）

后端**首次启动时**会自动在数据库中创建默认管理员账号（若表中尚不存在），无需单独执行建表或 seed 命令。

### 8.1 默认账号与首次登录

- **用户名**：`root`
- **初始密码**：`root`
- 使用浏览器打开前端登录页（online 模式），用上述账号登录。
- 登录后请尽快在管理后台修改密码（见下文）。

### 8.2 若未自动创建管理员

若初次部署时数据库尚未就绪（例如先启动了后端、后执行迁移），可能导致启动时未写入管理员。处理方式：

1. 确保已执行 **5.2 创建库与账号** 以及 **6.2 中的数据库表结构**（`prisma db push` 或 `prisma migrate deploy`）。
2. **重启后端服务**，启动时会再次执行默认管理员创建逻辑：

```bash
pm2 restart smart-cto-backend
```

3. 再次尝试使用 `root` / `root` 登录。

### 8.3 修改 root 密码

- **推荐**：使用 root 登录后，打开 **管理员后台**（`admin.html`），在「修改 root 管理员密码」区域输入新密码（至少 6 位）并保存。
- **命令行**：若已持有管理员 JWT，可调用接口修改：

```bash
curl -X PUT 'http://127.0.0.1:3000/api/admin/users/root/password' \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer 你的管理员JWT" \
  -d '{"password":"新密码至少6位"}'
```

## 9. 前端部署

### 9.1 生产环境配置

- 若项目提供 `frontend/.env.production.example`，可复制为 `frontend/.env.production`，并只配置后端 API 公网地址，例如：

```env
VITE_BACKEND_API_BASE_URL=https://你的域名或IP/api
```

- 前端运行时还会加载 `config.js` 和 `config.local.js`。**在线模式**下需让前端知道后端 API 地址：
  - 若 Nginx 与前端同域，且 `/api` 已反代到后端，则 `BACKEND_API_URL` 应设为 `https://你的域名/api`（或 `http://你的IP/api`）。
  - 可在构建产物 `frontend/dist` 根目录放置 `config.local.js`（不提交仓库），内容示例：

```javascript
window.APP_CONFIG = window.APP_CONFIG || {};
window.APP_CONFIG.MODE = 'online';
window.APP_CONFIG.BACKEND_API_URL = 'https://你的域名/api';
```

### 9.2 安装与构建

```bash
cd /srv/do1_smart_cto/frontend
npm install
npm run build
```

构建产物目录：`/srv/do1_smart_cto/frontend/dist`。

若前端无 `npm run build`，则直接将源码中的静态资源（如 `index.html`、`js`、`styles.css`、`config.js` 等）部署到 Nginx 的 root 目录，并确保上述 `config.local.js` 中 `MODE` 与 `BACKEND_API_URL` 正确。

## 10. Nginx 反向代理示例

配置文件示例：`/etc/nginx/sites-available/smart-cto`（将 `YOUR_DOMAIN_OR_IP` 改为实际域名或 IP）：

```nginx
server {
    listen 80;
    server_name YOUR_DOMAIN_OR_IP;

    root /srv/do1_smart_cto/frontend/dist;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass http://127.0.0.1:3000/api/;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location /health {
        proxy_pass http://127.0.0.1:3000/health;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
    }
}
```

启用并重载：

```bash
sudo ln -sf /etc/nginx/sites-available/smart-cto /etc/nginx/sites-enabled/smart-cto
sudo nginx -t
sudo systemctl reload nginx
```

## 11. HTTPS（推荐）

有域名时建议配置 SSL：

```bash
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d YOUR_DOMAIN
```

按提示选择是否重定向 HTTP 到 HTTPS。

## 12. 上线前检查清单

- [ ] 虚拟机系统与版本确认
- [ ] SSH 与 Git 可用
- [ ] Node 24、MariaDB/MySQL、Nginx、PM2 已安装
- [ ] 数据库 `do1_smart_cto` 与账号已创建，`DATABASE_URL` 可连通
- [ ] `npx prisma db push` 或 `npx prisma migrate deploy` 已执行
- [ ] 后端 `.env` 中 `HOST`、`PORT`、`DATABASE_URL` 正确，可选 `JWT_SECRET`
- [ ] 后端 PM2 进程 `smart-cto-backend` 运行中
- [ ] `curl http://127.0.0.1:3000/health` 返回正常
- [ ] `GET /api/ai/config` 可用，已通过 `PUT /api/ai/config` 写入 AI Key（勿写在前端）
- [ ] 前端已构建，`dist` 或静态资源已就绪，且 `MODE=online`、`BACKEND_API_URL` 指向公网 `/api`
- [ ] Nginx 反向代理已启用，`nginx -t` 通过
- [ ] 浏览器可打开前端页面，登录、创建案例、AI 功能可正常使用
- [ ] 默认管理员 `root`/`root` 已由后端启动时自动创建，首次登录后请在管理后台（admin.html）修改 root 密码

## 14. 部署前需确认的信息

- 虚拟机系统与版本
- SSH 登录用户与权限
- 公网 IP 或域名
- 数据库是否与本机在同一台机器（若否，需改 `DATABASE_URL` 的 host）
- 是否立即配置 HTTPS
- 是否采用 `/srv/do1_smart_cto` 作为部署路径（若否，文中路径需一并替换）

# Task Contract v1：为什么需要任务合同

## 元数据

- 适用模块：multi（架构 owner 派工与全链路）
- 关联：`docs/agents/architect/02-playbooks.md` 第 2 节
- 状态：active

## 现象

高风险或跨端任务在未对齐「做到哪、不做什么、谁以什么为真」的情况下开工，容易出现：

- 范围在实现过程中膨胀，验收时才发现与预期不一致；
- 前后端各自假设「真相源」，接口与 UI 行为冲突；
- 排障时在聊天、代码与文档之间反复横跳，缺少可引用的冻结口径；
- P0 / 鉴权 / 状态机等改动回滚成本高，一次误解带来多次返工。

## 根因

对话与即兴派工**默认不包含**完整的范围边界、责任划分与证据约定；而台账条目模板偏「跟谁、什么状态」，不足以单独承担**合同级**的冻结信息。

## 结论 / 口径

- **Task Contract v1** 是在开工前写下的最小一致面：目标、范围、排除项、影响面、真相源、验收、证据与拆工结果。
- 与 `03-active-tasks.md` **配合使用**：台账管「谁在做什么」；合同管「本轮冻结什么」——二者链接或同屏出现即可。
- 使用范围（满足任一）：P0；跨前后端；状态源 / 鉴权 / 导入导出 / 报告页 / 任务状态机等高风险主题。

## 操作步骤或验证方式

1. 判定任务是否落入使用范围（见上）。
2. 复制 `02-playbooks.md` 中的最小模板，填完再派工。
3. 派工提示词与可转发指令与合同一致；验收与证据按合同执行。

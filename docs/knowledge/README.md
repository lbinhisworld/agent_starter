# 知识库（Knowledge）

> **定位**：沉淀**可复用**的缺陷根因、排障步骤、契约口径与「以后别再踩坑」的结论。  
> **不是**：任务流水账、每日站会、或替代 `docs/agents/*/03-active-tasks.md` 的进展记录。

## 与任务台账的关系

| 维度 | `docs/agents/*/03-active-tasks.md` | `docs/knowledge/` |
| ---- | ----------------------------------- | ----------------- |
| 回答的问题 | **谁在做什么、做到哪一步** | **这类问题曾经怎么解决、根因是什么** |
| 生命周期 | 随任务开闭更新，可归档或删除索引行 | 长期保留；以主题为单位迭代 |
| 缺陷类内容 | 可只保留任务编号 + 知识卡链接 | **结论与复现条件**写知识卡，台账引用链接 |
| owner 总控 | `architect-owner.md` 中 ARCH 台账 | 跨领域结论放 `cross-cutting/` 或 `product/` |

**协作方式**：

1. 任务关闭前或复盘时，若存在可复用经验，**提炼一张知识卡**（或更新已有卡），在对应 agent 的 `03-active-tasks.md` 或任务条目中增加「知识卡：…」链接。
2. 同一缺陷在多处任务重复出现时，**以知识卡为单一事实来源**，台账不再展开长文。

## 目录约定

| 目录 | 用途 |
| ---- | ---- |
| `frontend/` | 前端 UI、路由、缓存、与后端契约相关的可复用结论 |
| `backend/` | 鉴权、数据库、部署、AI 代理链路等可复用结论 |
| `cross-cutting/` | 前后端接口协作、全链路排障、安全与性能等横切主题 |
| `product/` | 产品口径、版本取舍、非纯技术类但需冻结的结论（与 `business-product-agent` 配合） |

## 命名规则

- **文件**：`kebab-case.md`，建议带**日期或主题前缀**以便检索，例如：
  - `2026-03-23-put-problem-case-empty-body-404.md`
  - `ai-chat-upstream-502-vs-500.md`
- **避免**：`note.md`、`fix.md` 等无主题名；同一主题迭代时优先**编辑原卡**并更新文末「修订记录」，少拆碎片文件。
- **一篇一事**：一张知识卡聚焦一个根因或一条口径；若篇幅过长，拆成系列并在文首互链。

## 知识卡推荐结构（模板）

```markdown
# {短标题}

## 元数据

- 适用模块：frontend | backend | multi
- 关联任务（可选）：FE-* / BE-* / ARCH-*
- 状态：draft | active | superseded（被哪篇替代）

## 现象

## 根因

## 结论 / 口径

## 操作步骤或验证方式

## 修订记录

- YYYY-MM-DD：初稿 / 修订说明
```

## 与 agent 主文档的边界（ARCH-20260325-01）

- `docs/agents/*/00-core.md`：**≤200 行**，只放准则，不放动态流水。
- 缺陷「故事」和长篇排障过程：**进知识库**；主文档仅保留链接或一句摘要。

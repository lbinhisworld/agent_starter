# Smart CTO 当前已完成业务建表设计

**说明**：本文档以当前仓库中 `backend/prisma/schema.prisma` 及 `backend/prisma/migrations/` 为准，梳理已落地的表结构。表名、字段名与 Prisma 一致（驼峰），MySQL 中即为此命名。

---

## 一、表总览

| 表名 | 用途 |
|------|------|
| `ProblemCase` | 客户档案主表，首页解析后创建的客户档案与详情页主记录 |
| `ProblemCaseMessage` | 案例沟通消息表，详情页沟通历史与消息流 |
| `AppSetting` | 应用配置键值表（如 AI Key 等） |
| `AdminUser` | 管理员账号表 |
| `AppUser` | 业务用户账号表（含启用/停用状态） |

---

## 二、ProblemCase（客户档案主表）

- **主键**：`id`（VARCHAR(191)，业务侧传入）
- **时间**：`createdAt`、`updatedAt`（DATETIME(3)）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | VARCHAR(191) | 案例 ID，唯一 |
| customerName | VARCHAR(191) | 客户名称 |
| customerNeedsOrChallenges | TEXT | 客户需求或挑战 |
| customerItStatus | TEXT | 客户 IT 现状 |
| projectTimeRequirement | TEXT | 项目时间要求 |
| currentMajorStage | INT | 当前大阶段（0 需求理解，1 工作流对齐，2 ITGap，3 IT 策略） |
| currentItStrategySubstep | INT | IT 策略当前子步骤 |
| completedStages | JSON | 需求理解已完成子步骤索引 |
| workflowAlignCompletedStages | JSON | 工作流对齐已完成子步骤索引 |
| itGapCompletedStages | JSON | ITGap 分析已完成子步骤索引 |
| completedTaskIds | JSON | 已完成任务 ID 列表 |
| basicInfo | JSON | 客户基本信息结果 |
| bmc | JSON | 商业模式画布结果 |
| requirementLogic | JSON | 需求逻辑结果 |
| valueStream | JSON | 价值流结果 |
| globalItGapAnalysisJson | JSON | 全局 ITGap 分析结果 |
| localItGapSessions | JSON | 局部 ITGap 会话 |
| localItGapAnalyses | JSON | 角色汇总设计结果 |
| rolePermissionSessions | JSON | 角色权限分析会话 |
| coreBusinessObjectSessions | JSON | 核心业务对象推演会话 |

---

## 三、ProblemCaseMessage（案例沟通消息表）

- **主键**：`id`（VARCHAR(191)）
- **外键**：`caseId` → `ProblemCase(id)`，ON DELETE CASCADE
- **索引**：`(caseId, timestamp)`、`(caseId, taskId)`

| 字段 | 类型 | 说明 |
|------|------|------|
| id | VARCHAR(191) | 消息 ID |
| caseId | VARCHAR(191) | 所属案例 ID |
| taskId | VARCHAR(191) | 所属任务 ID（如 task1、task2、global-itgap） |
| taskName | VARCHAR(191) | 任务名称 |
| role | VARCHAR(191) | 消息角色：user / assistant / system |
| type | VARCHAR(191) | 消息类型：text、basicInfoCard、bmcCard 等 |
| content | LONGTEXT | 消息正文 |
| payloadJson | JSON | 扩展载荷 |
| confirmed | BOOLEAN | 是否已确认 |
| timestamp | DATETIME(3) | 消息时间 |
| createdAt / updatedAt | DATETIME(3) | 创建/更新时间 |

---

## 四、AppSetting（应用配置表）

- **主键**：`key`（VARCHAR(191)）

| 字段 | 类型 | 说明 |
|------|------|------|
| key | VARCHAR(191) | 配置键 |
| value | LONGTEXT | 配置值 |
| description | VARCHAR(191) | 说明 |
| createdAt / updatedAt | DATETIME(3) | 创建/更新时间 |

用于存储后端需要的配置（如 AI API Key 等），由管理端或运维维护。

---

## 五、AdminUser（管理员表）

- **主键**：`id`（VARCHAR(191)，默认 cuid）
- **唯一**：`username`

| 字段 | 类型 | 说明 |
|------|------|------|
| id | VARCHAR(191) | 主键 |
| username | VARCHAR(191) | 登录名，唯一 |
| passwordHash | VARCHAR(191) | 密码哈希 |
| createdAt / updatedAt | DATETIME(3) | 创建/更新时间 |

---

## 六、AppUser（业务用户表）

- **主键**：`id`（VARCHAR(191)，默认 cuid）
- **唯一**：`username`

| 字段 | 类型 | 说明 |
|------|------|------|
| id | VARCHAR(191) | 主键 |
| username | VARCHAR(191) | 登录名，唯一 |
| passwordHash | VARCHAR(191) | 密码哈希 |
| status | VARCHAR(191) | 启用状态：`ENABLED` / `DISABLED`，默认 `ENABLED` |
| createdAt / updatedAt | DATETIME(3) | 创建/更新时间 |

---

## 七、任务摘要为何不单独建表

当前 `/api/problem-cases/:id/tasks` 的任务摘要仍由 `ProblemCase` 的 `currentMajorStage`、`completedStages`、`workflowAlignCompletedStages`、`it_gap_completed_stages`、`completedTaskIds` 等字段推导生成，因此未单独建任务表。若后续需要任务写入、回退、重启或操作审计，可再增加例如 `problem_case_task_states`、`problem_case_operation_logs` 等表。

---

## 八、当前状态与维护方式

- **已落地**：上述 5 张表已通过 Prisma migration（如 `20260318183001_init_auth`）在库中创建。
- **维护**：以 `backend/prisma/schema.prisma` 为唯一模型定义，改表后执行 `npx prisma migrate dev`（开发）或 `npx prisma migrate deploy`（线上），勿再手写建表 SQL 与文档不一致。

# FE-20260411-14 · 冻结 B 线 online-only 边界

## 1. 任务元数据

- 任务编号：`FE-20260411-14`
- Phase：`2A`
- owner：`frontend`
- 优先级：`P0`
- 状态：`completed`

## 2. 任务目标

- 冻结 B 线首批只覆盖 `online` 的边界。
- 明确 `local` 不迁移、不清理、不纳入首批阻塞项。
- 阻止后续实现把 local 兼容错误带入首批统一工程计划。

## 3. 当前事实

- 当前专项已经明确 B 线只考虑 `online`。
- 若不在任务卡层继续写死边界，后续实现很容易顺手把 local 拉进来，导致范围膨胀。
- online-only 同时受后端鉴权、拒绝访问、深链恢复与 bundle 刷新语义约束，不是前端单边口径。
- local 场景的存储、执行与数据源语义与 online 并不完全相同。

## 4. In Scope

- online-only 适用范围
- local 不纳入迁移的说明
- 与后端鉴权 / 拒绝访问 / 深链恢复合同的衔接
- 与 cutover、fixture、首批接管范围的边界衔接

## 5. Out Of Scope

- local 场景治理方案
- local 历史数据清理
- local 与 online 的统一抽象设计

## 6. 前置依赖

- `ARCH-20260411-07`

## 7. 实施说明

1. 在 B 线任务卡中重复冻结 online-only 口径。
2. 明确 local 不迁移、不清理、不作为首批 cutover 阻塞项。
3. 把 fixture、host、双渲染与 cutover 全部限定在 online 场景。
4. 明确前端 online-only 定义必须与后端访问、鉴权、拒绝访问和深链恢复合同对齐。
5. 避免后续实现将 local 行为作为验收前提。

### 7.1 online-only 的固定定义

| 项 | 固定口径 |
| --- | --- |
| `online` 的含义 | `APP_CONFIG.MODE === 'online'`，详情数据经 `STORAGE_HTTP_ADAPTER`、`problemCaseApi`、后端鉴权与 bundle refresh 链进入页面 |
| `local` 的含义 | `APP_CONFIG.MODE === 'local'`，详情与 AI 调用走 IndexedDB / localStorage / 直连模型或本地占位逻辑 |
| 本卡排除的 `local` | 指运行模式与存储/鉴权分支，不是 task9 的业务命名 `local-itgap` |
| 首批迁移口径 | 只迁移 online 详情访问链路，不迁移 local 运行模式的登录、存储、模型调用与门禁分支 |

### 7.2 B 线首批纳入范围

| 纳入项 | 当前依据 | 说明 |
| --- | --- | --- |
| `index.html?caseId=` 深链打开 | `main.js` `openProblemDetailByCaseId` / `refreshProblemDetailBundleFromBackend` | same URL online 详情主链 |
| `STORAGE_HTTP_ADAPTER` 与 HTTP hydration | `frontend/js/storage-http-adapter.js` | online 案例列表、详情、聊天与 task summaries 的数据来源 |
| `problemCaseApi` bundle refresh / task action | `frontend/js/core/problem-case-api.js` | online 详情刷新与动作入口 |
| 鉴权续期、401/403/404/428 / `AI_CONFIG_REQUIRED` 门禁 | `frontend/js/auth-runtime.js`、`frontend-vue/src/api/client.ts`、后端 contract | 前后端共同合同，前端不能自行发明第二套语义 |
| `model-config.html`、`login.html`、`home.html` 等 online 关联跳转页 | 当前真实发布拓扑 | 作为 online 访问链路的一部分继续保留 |

### 7.3 明确排除的 local 分支

| 排除项 | 当前依据 | 固定口径 |
| --- | --- | --- |
| `STORAGE_INDEXEDDB_ADAPTER` | `frontend/js/storage-indexeddb-adapter.js` | 保留现状，不纳入 Vue 统一详情实施 |
| local 登录占位与本地 token 签发 | `frontend-vue/src/login/LoginPage.vue` | 不作为首批详情迁移验收前提 |
| local 模式直连 DeepSeek / 本地 AI 调用链 | `frontend/js/api.js` | 不纳入 host、fixture、cutover 首批合同 |
| local 模式下 `model-config` 页面“无需配置”口径 | `frontend-vue/src/model-config/ModelConfigPage.vue` | 不进入 online cutover 验收 |
| local-only 管理页 / 联调兜底口径 | `frontend-vue/src/admin/AdminPage.vue` | 保留现状，不阻塞详情迁移 |

### 7.4 易混边界澄清

| 容易混淆项 | 固定解释 |
| --- | --- |
| `local` 运行模式 vs `local-itgap` 任务名 | 本卡排除的是运行模式，不是 task9 业务阶段；task9 在 online 详情里仍然存在 |
| `local` 存储分支 vs online bundle refresh | 二者是两套数据入口；B 线首批只承接 online 的 HTTP / bundle 链 |
| local 页面仍存在 vs local 纳入迁移 | 页面继续保留不等于纳入首批迁移；本专项只要求不破坏，不要求统一承接 |

### 7.5 与后续任务的衔接要求

| 后续任务 | 必须继承的边界 |
| --- | --- |
| `BE-20260411-01` | 只冻结 online 鉴权、拒绝访问、AI 配置门禁与 bundle 语义，不补 local 合同 |
| `FE-20260411-15` | 首批接管范围只讨论 online 详情壳层，不把 local UI 差异带进范围 |
| `FE-20260411-16` | 同 URL 技术切换合同只面向 online 详情，不为 local 增加第二套入口接线 |
| `FE-20260411-17` 至 `FE-20260411-21` | fixture / 双渲染只基于 online 输入快照验收 |
| `ARCH-20260411-08` / `FE-20260411-22` / `FE-20260411-23` | readiness、灰度、切回都只对 online 生效 |

### 7.1 online 详情访问链最小 API 合同

| 路径 | method | 作用 | 固定口径 |
| --- | --- | --- | --- |
| `/api/problem-cases/:id` | `GET` | 获取案例详情 | path / method 固定，不新增“Vue 专用详情接口” |
| `/api/problem-cases/:id/messages` | `GET` | 获取聊天消息 | 与详情同 caseId、同 owner isolation 语义 |
| `/api/problem-cases/:id/tasks` | `GET` | 获取任务摘要 | 与详情同 caseId、同 owner isolation 语义 |
| `/api/problem-cases/:id/tasks/:taskId/start` | `POST` | 启动任务 | 返回更新后的任务 bundle 结果，不改 path 语义 |
| `/api/problem-cases/:id/tasks/:taskId/confirm` | `POST` | 确认任务 | 返回更新后的任务 bundle 结果 |
| `/api/problem-cases/:id/tasks/:taskId/revise` | `POST` | 进入修订 | 返回更新后的任务 bundle 结果 |
| `/api/problem-cases/:id/tasks/:taskId/rollback` | `POST` | 回滚任务 | 返回更新后的任务 bundle 结果 |
| `/api/ai/chat` | `POST` | online AI 代理调用 | 用户级 AI 配置未满足时必须返回 `428 + AI_CONFIG_REQUIRED` |
| `/api/me/ai-config/status` | `GET` | 当前用户 AI 配置门禁检查 | 业务页首屏主动门禁查询；admin 会被 403 拒绝 |

### 7.2 401 / 403 / 404 / 428 语义冻结表

| 状态码 | 触发场景 | 固定语义 | 前端使用方式 |
| --- | --- | --- | --- |
| `401` | JWT 缺失、非法、过期、session 不存在/已撤销 | 认证失效 | 前端清 token 并跳 `login.html`；不得把业务拒绝或上游模型失败伪装成 401 |
| `403` | 已登录但账号被停用；或访问不匹配角色的受保护接口（如 admin / me-ai-config） | 已认证但角色或账号状态不允许 | 前端提示但不应把 detail owner isolation 解释成 403 |
| `404` | 案例不存在；或普通用户无权访问他人案例 | detail owner isolation 与 not found 统一口径 | 详情深链 / bundle refresh 遇到 404 视为“案例不存在或无权访问”，不区分是缺失还是越权 |
| `428` + `AI_CONFIG_REQUIRED` | 业务用户未完成个人模型配置验证时调用 `/api/ai/chat` | AI 配置门禁 | 前端统一跳 `model-config.html?redirect=...` |

### 7.3 owner isolation 合同

| 项 | 固定口径 |
| --- | --- |
| user 可见范围 | 仅自己创建 / 导入的案例 |
| admin 可见范围 | 可查看全部案例 |
| 历史 owner 为空案例 | user 不可见，admin 可见 |
| detail / messages / tasks / report / export / write case 的越权访问 | 对 user 一律返回 `404`，不暴露“案例存在但无权限”的侧信道 |
| 文档 / 测试依据 | `backend/tests/problem-cases-owner-isolation.test.ts` 已覆盖上述语义 |

### 7.4 AI 配置门禁与 redirect 合同

| 环节 | 固定口径 |
| --- | --- |
| 后端强制门 | `/api/ai/chat` 在业务用户缺少已验证配置时，必须返回 `428` 与 `code: AI_CONFIG_REQUIRED` |
| 前端主动门 | 业务页首屏可先调 `/api/me/ai-config/status`，若未 ready/gatePassed 则前端主动跳转 |
| redirect 目标页 | `model-config.html` |
| redirect 参数 | 前端负责带上当前业务页安全 `redirect`，后端不发明第二种跳转参数协议 |
| 普通失败区分 | 上游模型商 401 必须映射为 `502 + AI_UPSTREAM_AUTH_FAILED`，不得与 JWT 401 混淆 |

### 7.5 “bundle refresh” 的真实合同

| 项 | 固定口径 |
| --- | --- |
| 实现方式 | 当前不是单独后端 bundle API，而是前端 `STORAGE_HTTP_ADAPTER.refreshProblemDetailBundle()` 顺序拉取 detail / messages / tasks 三段数据后本地组装 |
| 对后端的要求 | 三个 GET 接口必须长期保持 caseId 一致、owner isolation 一致、字段语义一致 |
| 失败处理 | 任一 GET 返回 `404/403`，前端视为 access denied / missing；非 `404/403` 可退回缓存并保留旧快照 |
| 迁移约束 | B 线不得为了 Vue shell 私自增加第二套 detail-bundle API 作为首批前提 |

### 7.6 深链恢复合同

| 项 | 固定口径 |
| --- | --- |
| 对外入口 | `index.html?caseId=` |
| 前端行为 | URL 带 `caseId` 时允许先以 stub 打开，再通过 refresh 链向后端拉 detail / messages / tasks |
| 后端责任 | 只要 caseId 合法且用户有权访问，上述三段 GET 必须可独立恢复当前案例；若无权或不存在，返回 404 供前端安全收口 |
| 禁止项 | 不要求前端依赖隐藏字段、临时映射或“先 list 再猜 case”才能恢复深链 |

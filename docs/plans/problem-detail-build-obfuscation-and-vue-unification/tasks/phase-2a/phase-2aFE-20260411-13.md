# FE-20260411-13 · 建立 host / selector / command 合同

## 1. 任务元数据

- 任务编号：`FE-20260411-13`
- Phase：`2A`
- owner：`frontend`
- 优先级：`P0`
- 状态：`completed`

## 2. 任务目标

- 建立 Vue 壳层与 legacy/runtime 内核之间的 host / selector / command 合同。
- 明确输入输出、错误态、loading 态与案例绑定方式。
- 保证 Vue shell 不需要直接读取 legacy 私有状态。

## 3. 当前事实

- Vue 壳层若没有稳定 host 合同，就会倾向于直接依赖 `window`、DOM 或 legacy 内部状态。
- 要保证逻辑完全一致，最稳方式不是复制语义，而是收紧壳层与内核的调用面。
- 当前详情在一次异步 bundle refresh 后会同时重算 item、messages、task summaries、viewing stage 并重绘多个区域。
- selector 与 command 若没有分离，展示层和动作层会再次耦合在一起。

- selector 字段与 command 输入输出边界
- command 完成后 UI 如何得到新快照的更新机制
- loading、error、case 绑定与异常处理口径

## 5. Out Of Scope

## 7. 实施说明

1. 定义 host 作为唯一桥接面，向 Vue shell 暴露 selector 与 command。
2. selector 只提供只读状态与展示所需数据，不暴露 legacy 内部可变状态引用。
3. command 只复用原动作链，不新建第二套 Vue 版业务逻辑。
4. 明确异步 command 完成后 UI 如何更新，包括事件、订阅、失效、重新拉 selector 或返回新 snapshot 的唯一机制。
5. 明确错误态、loading 态、案例绑定、无效 case 与异常返回的标准口径。

### 7.1 host 顶层合同

| 合同项 | 固定口径 |
| --- | --- |
| 宿主形态 | `ProblemDetailHost` 是 Vue shell 与 legacy/runtime 内核之间的唯一桥接面 |
| 数据读取方式 | Vue shell 只能通过 host 的 selector 读取快照，不能直接读取 `window`、DOM、`SmartCto.problemDetailRuntime.__host`、`problemDetailWaitingForFeedback` 或 `__appState` 私有对象 |
| 动作触发方式 | Vue shell 只能通过 host 的 command 触发动作，不得直接调用 `main.js`、runtime 或 task 模块的散落函数 |
| 更新方式 | host 只提供单一订阅机制；异步 command 结束后由 host 发布新 snapshot，Vue shell 再重新拉 selector |
| 真相源基础 | selector 的上游只能来自 `app-state`、canonical task 结果、task1 resolved preliminary requirement、task summaries 与 host 内部受控派生值 |
| 首批适用范围 | 先覆盖壳层、导航、步骤条、历史侧栏、loading / error / empty 所需的最小合同；高编排 task 业务动作继续走 legacy 内核 |

### 7.2 推荐接口骨架

```ts
type ProblemDetailHost = {
  getBinding(): ProblemDetailCaseBinding
  selectors: ProblemDetailSelectors
  commands: ProblemDetailCommands
  subscribe(listener: (event: ProblemDetailHostEvent) => void): () => void
}
```

### 7.3 case 绑定合同

| 字段 | 类型 | 固定口径 |
| --- | --- | --- |
| `caseId` | `string` | 当前详情唯一案例标识；与公开 URL `index.html?caseId=` 对齐 |
| `caseKey` | `string` | 内存 / 存储绑定键；与 `problemDetailChatMessagesCaseKey` 同源，用于防串案 |
| `mode` | `'online'` | B 线首批固定 `online`，不暴露 `local` 分支 |
| `bindingStatus` | `'idle' \| 'binding' \| 'ready' \| 'error'` | 壳层只根据该状态决定是否渲染加载、错误或正常态 |
| `snapshotVersion` | `number` | host 单调递增版本号；每次有效快照更新都必须递增 |

### 7.4 selector 合同

#### 7.4.1 selector 总规则

1. selector 只返回可序列化、只读、无副作用的数据快照。
2. selector 不返回 DOM 节点、函数、可变数组引用或 legacy 模块私有对象。
3. selector 的返回值允许按区域拆分，但都必须来自同一 `snapshotVersion`。
4. Vue shell 不允许持有 selector 结果做长期缓存并自行增量 patch；收到 host 事件后必须重新读取。

#### 7.4.2 必备 selector 清单

| selector | 主要字段 | 上游来源 | 用途 |
| --- | --- | --- | --- |
| `getShellSnapshot()` | `caseId`、`snapshotVersion`、`loadState`、`errorState`、`header`、`viewState`、`panelState` | `app-state` + host 派生 | 壳层总入口；用于顶部、空态、错误态、刷新态 |
| `getHeaderSnapshot()` | `archiveNo`、`customerName`、`requirementTitle`、`caseHeadline` | `currentProblemDetailItem` + `buildCaseRequirementHeadlineParts` | 顶栏与案例标题 |
| `getTaskNavigationSnapshot()` | `currentMajorStage`、`viewingMajorStage`、`canonicalTaskId`、`viewingTaskId`、`taskSteps[]` | `currentProblemDetailItem` + canonical task + renderer 同源派生 | 步骤条、导航与当前任务高亮 |
| `getHistorySidebarSnapshot()` | `summary`、`taskTree`、`tabs`、`activeTaskId`、`historyStatus` | `currentProblemDetailItem` + messages + task summaries | 历史侧栏与四类 tab 的 Vue 接管输入 |
| `getLegacyMountSnapshot()` | `workspaceMountMode`、`chatMountMode`、`historyMountMode`、`loadingOverlay`、`emptyState` | host 内部派生 | 决定哪些区域继续挂 legacy，哪些区域由 Vue 壳层接管 |

#### 7.4.3 selector 字段边界

| 字段族 | 必须暴露 | 禁止暴露 |
| --- | --- | --- |
| header | `archiveNo`、案例标题、客户名、需求标题 | DOM 文本节点、legacy 组件实例 |
| navigation | canonical task、viewing task、阶段索引、步骤状态 | 依赖点击顺序才能还原的临时变量 |
| history sidebar | 任务树、汇总指标、详情 / 过程日志 / Skill / 审计 Skill 四类 tab 所需结构 | `communication-history.js` 的内部缓存对象、HTML 字符串拼装中间态 |
| status | `loadState`、`errorState`、`pendingCommand`、`lastUpdateCause` | 任意直接面向用户的拼装文案以外的隐式异常对象 |
| task1 shared | resolved preliminary requirement 的只读摘要、是否存在跟进态 | `preliminaryRequirement.js` 私有 helper 引用、原始可变对象引用 |

### 7.5 command 合同

#### 7.5.1 command 总规则

1. command 只负责触发既有 legacy/runtime 动作链，不新增第二套 Vue 版业务逻辑。
2. command Promise 只返回“动作受理结果”，不直接返回权威业务状态。
3. command 成功后的新 UI 数据必须来自后续 selector 重新读取。
4. command 必须带 `caseId` 或使用当前 binding 校验；若 case 失配则直接拒绝，不得把旧请求写到新 case。

#### 7.5.2 首批必备 command

| command | 输入 | 输出 | 固定口径 |
| --- | --- | --- | --- |
| `openCase(caseId)` | `caseId` | `CommandReceipt` | 绑定详情案例、触发首帧加载与快照发布 |
| `refreshCase(caseId?)` | 当前或显式 `caseId` | `CommandReceipt` | 复用 `refreshProblemDetailBundleFromBackend` 与既有 hydrate 链 |
| `focusTask(taskId)` | `taskId` | `CommandReceipt` | 只更新 viewing / focus，不重写 canonical task 判定 |
| `toggleHistory(open)` | `boolean` | `CommandReceipt` | 控制历史侧栏开关，不修改业务状态 |
| `retryLastLoad()` | 无 | `CommandReceipt` | 对最近一次失败加载或刷新重试，复用既有 refresh 链 |

#### 7.5.3 保留但不在首批接管范围内的 command

| command 家族 | 当前判断 |
| --- | --- |
| 聊天发送 / Ask-Agent 模式切换 | 继续由 legacy 区域承接，待后续批次再显式纳入 host 合同 |
| task1 / task4 / task8 / task10 / task11 的高编排确认、修改、重做 | 首批不迁移，不纳入当前 Vue 壳层 command 面 |
| rollback / restart current / flow exception resume | 保留在 legacy 内核，待 cutover 前再决定是否外提 |

### 7.6 统一命令回执合同

```ts
type CommandReceipt = {
  accepted: boolean
  command: string
  caseId: string
  requestId: string
  expectedVersion: number
}
```

固定口径：

1. `expectedVersion` 表示 host 期望后续发布的新快照版本，不等于“最终业务已完成”。
2. Vue shell 收到回执后只能等待订阅事件或重新读 selector，不能拿回执当最终状态。
3. 同一 `requestId` 对应的异步动作若因 case 切换失效，host 可以丢弃结果且不发布旧 case 快照。

### 7.7 单一状态更新机制

| 环节 | 固定口径 |
| --- | --- |
| 发布入口 | 只有 `host.subscribe()` 一个入口 |
| 事件载荷 | `caseId`、`snapshotVersion`、`cause`、`pendingCommand`、`loadState` |
| 读取方式 | 事件只做“通知”；完整数据必须重新调用 selector 读取 |
| 更新时机 | host 完成 `app-state` 更新、hydrate、canonical task 重算与必要派生后，统一发布一次新快照 |
| 中间态 | 若命令耗时较长，可先发布 `loadState='loading'` + `pendingCommand`，完成后再发布 `loadState='ready'` 或 `error` |
| 禁止项 | 禁止 Vue shell 通过命令返回值、DOM diff、legacy 私有状态或局部事件拼接出“半快照” |

### 7.8 loading / error / empty 合同

| 状态 | 条件 | 壳层行为 |
| --- | --- | --- |
| `empty` | 当前无有效 `caseId` 或 host 尚未绑定成功 | 不渲染详情内容；等待 `openCase` 或同 URL 绑定完成 |
| `loading` | 首帧打开、bundle refresh、retry、切案中 | 渲染壳层级 loading；必要时沿用 legacy 刷新遮罩 |
| `ready` | selector 可提供完整快照 | 按快照渲染 Vue 壳层 |
| `error.notFound` | case 不存在或无可访问详情 | 显示不可访问 / 不存在态，并允许切回首页或重试 |
| `error.forbidden` | 在线访问被拒绝 | 视为访问拒绝态，不继续渲染旧 case 数据 |
| `error.unauthorized` / `error.aiConfigRequired` | 鉴权或 AI 配置门禁 | 保留 structured error / redirect hint，具体门禁语义由 `FE-20260411-14` / `BE-20260411-01` / `FE-20260411-16` 继续冻结 |
| `error.unknown` | 网络或未分类异常 | 展示通用错误与 retry 入口 |

### 7.9 最小闭环示例

1. `openCase(caseId)` 受理后，host 发布 `loadState='loading'`。
2. `main.js` 复用既有打开详情、hydrate、canonical task 与 refresh 链，写回 `app-state`。
3. host 在内核快照稳定后发布 `snapshotVersion + 1` 的事件。
4. Vue shell 收到事件后重新读取 `getShellSnapshot()`、`getTaskNavigationSnapshot()`、`getHistorySidebarSnapshot()`。
5. 若随后用户点击步骤条触发 `focusTask(taskId)`，host 只更新 viewing 状态并再次发布新快照，不改变 canonical task 真相源。

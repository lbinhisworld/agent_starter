## 2. 任务目标

- 定义 `frontend-vue` 如何承接统一详情入口与多入口产物链。
- 说明详情壳层入口如何与现有 `home`、`login`、`model-config` 共存。
- 冻结同一 `index.html?caseId=` 下 legacy / Vue shell 的 bootstrap、flag 与切回技术合同，并作为本专项后续灰度与 cutover 的唯一真相源。
- 确保 B 线接入构建工程时不破坏现有 Vue 产物组织。

## 3. 当前事实

- `frontend-vue` 已是现有多入口构建工程的承载方。
- 当前 `frontend-vue` 真实产物链已经固定输出 `login.html`、`admin.html`、`home.html`、`model-config.html` 以及共享 `frontend/vue-auth-assets/`，并由 `vite.config.ts` 负责清理目录、固定命名和 `version.txt` 写入。
- 当前 `frontend/index.html` 仍是唯一详情入口壳：无 `caseId` 时立即跳 `home.html`，有 `caseId` 时进入 legacy 详情链，并复用 `auth-runtime.js` 的首屏鉴权 / AI 配置门禁。
- 若详情入口如何进入 Vite 多入口不先讲清，后续实现会在入口命名、输出位置和共享产物上产生分歧。
- 单一公开 URL 下若没有唯一 bootstrap / flag / fallback 技术合同，Phase 3 灰度仍会卡在现场决策，且容易出现两份口径并行演化。
- B 线既要统一工程，又不能影响现有 Vue 页面产物链。

3. 明确在同一 `index.html?caseId=` 下由哪一层完成 bootstrap，legacy / Vue shell 的选择 flag 放在哪里、谁负责读取、优先级如何定义。
4. 冻结统一构建工程下的共享资源、详情壳层资源和 legacy 脚本链边界。
5. 说明切回 legacy 时怎样在同一 URL 下即时生效，而不依赖改入口地址。

7. 让后续实现者无需再决定详情入口落在哪个工程层级。

### 7.1 `frontend-vue` 统一详情入口的承接方式

| 项 | 固定口径 |
| --- | --- |
| 公开详情入口 | 仍然只有 `frontend/index.html?caseId=`；不新增 `problem-detail.html`、`detail.html` 或第二条外部详情 URL |
| `frontend-vue` 的角色 | 承接“详情壳层”静态资产构建，不承接新的公开详情 HTML 路由 |
| 详情壳层入口形态 | 新增 `frontend-vue` 内部详情壳层源码入口（建议 `src/problem-detail-shell/main.ts`）；如 Vite 为构建需要引入 source HTML，仅允许作为 build source，不得升格为公开入口真相源 |
| 对外产物形态 | 固定产出到 `frontend/vue-auth-assets/` 的 `problem-detail-shell.js` / `problem-detail-shell.css` 及其共享 chunk，不新增公共详情 HTML |
| 与现有入口共存 | 保持 `login` / `admin` / `home` / `model-config` 继续为 HTML 多入口；详情壳层作为 asset entry 与它们共用同一 `vue-auth-assets/` 目录和版本体系 |

### 7.2 多入口产物链合同

| 产物类目 | 当前/目标形态 | 固定口径 |
| --- | --- | --- |
| HTML 入口 | `frontend/login.html`、`frontend/admin.html`、`frontend/home.html`、`frontend/model-config.html` | 继续由 `frontend-vue` 产出并直接对外服务 |
| 详情公开入口 | `frontend/index.html` | 继续由 legacy 主站持有，负责 `caseId` 深链、`view=tools`、默认回落 `home.html` 与主脚本装载 |
| 详情壳层资源 | `frontend/vue-auth-assets/problem-detail-shell.js` / `.css` | 由 `frontend-vue` 构建产出，供 `index.html` 同源加载 |
| 共享资源 | `frontend/vue-auth-assets/shared-*.js`、共享 css/runtime | 与现有登录/首页/模型配置入口共用，不单独复制第二套目录 |
| 版本文件 | `frontend/vue-auth-assets/version.txt` | 写入逻辑必须把 `problem-detail-shell` 产物一并计入哈希，确保切换和回滚能统一破缓存 |

### 7.3 同 URL bootstrap 顺序合同

1. 浏览器访问 `index.html?caseId=` 后，先执行 `index.html` 现有“无 `caseId` 跳 `home.html`”的 URL 归一逻辑；有 `caseId` 时不得跳走。
2. 保持 `config.js` / `config.local.js` / `auth-runtime.js` 先于详情选择执行；缺 token、401 或 `428 + AI_CONFIG_REQUIRED` 的门禁继续分别跳 `login.html` / `model-config.html`，不由 Vue 壳层重新接管。
3. 只有在 `caseId` 存在且首屏门禁通过后，才允许执行“同 URL 详情壳层选择器”。
4. 同 URL 详情壳层选择发生在 `index.html` / 详情 bootstrap 协调层，早于实际详情渲染，但不得绕过 legacy 核心脚本链；因为 B 线首批仍依赖 legacy host/runtime 内核。
5. 不允许把选择逻辑散落到 `HomePage.vue`、`login.html`、后端跳转或人工换链接上解决。

### 7.4 同 URL flag 合同

| 优先级 | 来源 | 键名/形式 | 允许值 | 固定口径 |
| --- | --- | --- | --- | --- |
| 1 | URL 临时覆盖 | `?pdShell=` | `legacy` / `vue` | 仅用于联调、验收与紧急诊断；仍属于同一 `index.html?caseId=` 入口，不得作为第二公开入口传播 |
| 2 | 部署配置 | `window.APP_CONFIG.PROBLEM_DETAIL_SHELL` | `legacy` / `vue` | 作为环境级默认开关；Phase 3 灰度只允许调整这一层的分批启用策略 |
| 3 | 默认值 | 缺省 | `legacy` | 若无显式开关，一律回到 legacy |

补充固定口径：

1. `FE-20260411-22` 只定义“什么时候允许把部署配置从 `legacy` 切到 `vue`、谁批准、如何灰度”，不重新发明 flag 名字、优先级和取值。
2. 同 URL 选择器解析完毕后，应把最终结果暴露为单一只读决策值，供 legacy bootstrap 与 Vue 壳层共用；不得两边各算一遍。

### 7.5 同 URL 挂载与 fallback 合同

| 场景 | 固定行为 |
| --- | --- |
| 解析结果为 `legacy` | 直接走现有 `index.html` + `main.js` 详情链，`frontend-vue` 详情壳层资源可不加载 |
| 解析结果为 `vue` | 先保证 legacy host/runtime 内核可初始化，再挂载 Vue 壳层；Vue 只接 `FE-20260411-15` 允许的区块 |
| Vue 壳层资源加载失败 | 同一 URL 下立即回退 legacy，不改 `caseId`、不切页面路径 |
| Vue 壳层 mount 失败 / host 能力检查失败 | 同一 URL 下立即回退 legacy，并记录失败原因到运行时证据 |
| 运行时需要紧急切回 | 通过 `?pdShell=legacy` 或部署配置切回，不要求改动公开入口地址 |

强制要求：

1. Vue 壳层 fallback 不能依赖“跳去另一个 HTML 再回来”；必须留在当前 `index.html?caseId=` 完成。
2. 为保证 fallback 可行，`index.html` 现有 DOM id、legacy host 初始化点和 `main.js` 详情链不得在首批被 Vue 壳层破坏。
3. Vue 壳层即使接管壳层，也不能接管 auth gate、deep link 恢复和 case 访问决裁；这些仍以 `index.html` + `auth-runtime.js` + legacy host 为准。

### 7.6 与 `frontend/dist` / A 线发布拓扑的关系

1. A 线 `frontend/dist` 发布集合后续必须一并纳入：
   - `index.html`
   - `home.html`
   - `login.html`
   - `admin.html`
   - `model-config.html`
   - `vue-auth-assets/`（含 `problem-detail-shell` 与 `version.txt`）
2. `problem-detail-shell` 进入产物链后，不得要求部署额外补目录或补第二套静态站点路径。
3. 若 `frontend-vue` 构建新增详情壳层资产，`version.txt` 和 dist smoke 口径必须同步扩大，不能只构建不验。

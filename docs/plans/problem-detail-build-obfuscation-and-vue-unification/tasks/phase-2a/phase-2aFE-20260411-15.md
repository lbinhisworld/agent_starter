- Phase：`2A`

- 优先级：`P0`
- 状态：`completed`

## 2. 任务目标

- 冻结 B 线首批允许接管的 UI 范围。
- 只允许壳层、导航、步骤条、历史侧栏、loading/error/empty 等承接。
- 显式排除高编排任务节点的首批业务替换。

## 3. 当前事实

- B 线若没有首批范围冻结，最容易在实现时扩展到 task 级业务逻辑接管。
- 专项目标是先统一工程与壳层，再谈更深的业务替换。
- task1、task4、task8、task10、task11 都属于高风险节点，首批替换代价高。
- 当前历史侧栏已经不是“一个抽屉入口”，而是包含汇总指标、任务树以及详情 / 过程日志 / 任务 Skill / 审计 Skill 四类结构的完整投影视图。
- `frontend/index.html` 顶栏与详情工具条里同时存在返回、模型配置、沟通历史、回退、重启当前、异常继续、售前方案、导出、恢复等混合动作，若不拆清“谁只接壳层、谁仍保留 legacy 动作”，首批范围会被误读为整页替换。

## 7. 实施说明

1. 把首批接管范围限定在壳层、稳定展示层和只读投影视图，不把 task 业务编排一起带入。
2. 明确历史侧栏不是“只保留入口按钮”，而是允许 Vue shell 接管完整结构渲染，但数据仍来自 host selector / legacy projection。
3. 明确哪些按钮只允许接管布局与显隐，哪些动作仍必须通过既有 legacy/host 链执行，避免把首批范围误写成“整页完全 Vue 化”。
4. 明确 task1、task4、task8、task10、task11 及其语义处理链、聊天链和主工作区渲染不在首批替换范围。
5. 让后续 cutover readiness 只基于被允许接管的范围验收。

### 7.1 首批允许接管的范围清单

| 区块 | 允许接管到的粒度 | 允许依赖 | 首批允许动作 | 固定口径 |
| --- | --- | --- | --- | --- |
| 顶部壳层与导航 | 顶栏布局、返回入口、案例编号 badge、导航高亮、用户信息占位、模型配置入口位置 | `host.selectShellChrome()`、现有 online 跳转合同 | 返回首页/列表、模型配置跳转、被动展示当前案例标题与状态 | Vue shell 只承接壳层组织与受控导航，不重写登录态、鉴权或模型配置语义 |
| 步骤条 | task1-task15 的步骤条容器、状态样式、当前焦点态、禁用态 | `host.selectTaskStepper()` | `focusTask(taskId)` | 只允许接管步骤条显示与聚焦，不允许在步骤条内部重写 task 执行语义 |
| 历史侧栏 | 面板开关、汇总指标、任务树、四类 tab、对应 panel 结构、空态/错误态 | `host.selectHistorySidebar()`、同一快照下的历史投影 | `toggleHistory(open)`、task 节点展开/收起、tab 切换、只读复制类交互 | 历史侧栏首批是“结构级接管”，不是“只有入口按钮”；但它仍是只读投影视图，不得反向定义任务语义 |
| loading / error / empty | 壳层级 loading、not found / unauthorized / ai-config-required / unknown、空态占位 | `host.selectLoadState()` | `retryLastLoad()` | 状态展示必须与 `FE-20260411-13`、`FE-20260411-14`、`BE-20260411-01` 保持同一错误语义 |

### 7.2 历史侧栏的首批结构合同

| 结构块 | 首批要求 |
| --- | --- |
| 汇总区 | 至少覆盖总耗时、输入 token、输出 token 三项汇总及其单位/标题语义 |
| 任务树 | 至少覆盖 task 节点层级、任务名称、状态类、展开/收起结构 |
| tab 集合 | 至少覆盖 `任务详情`、`过程日志`、`任务Skill`、`审计Skill` 四个 tab 的顺序与显隐 |
| panel 集合 | 至少覆盖详情信息块、过程日志时间线、Skill 时间线、审计 Skill 时间线四类 panel 容器 |
| 首批限制 | 允许复用 legacy 现有结构化数据或 host selector 投影；不允许把历史面板派生结果回写成 canonical task、messages 或 current item 真相源 |

### 7.3 首批明确不接管的范围

| 排除项 | 排除原因 | 固定口径 |
| --- | --- | --- |
| 主工作区业务内容 | 当前由 runtime + legacy workspace 渲染，且直接承载任务语义 | 首批可保留 legacy island，不进入 Vue 业务替换 |
| 聊天消息列表、输入框、Ask/Agent 模式、发送链 | 涉及 `problem-detail-chat.js` 消息入口与动作编排 | 首批不迁移，继续由 legacy 区域承接 |
| task1 / task4 / task8 / task10 / task11 的确认、修改、重做与补充链 | 高编排、高状态密度、对语义一致性要求最高 | 明确排除在首批替换范围外 |
| rollback / restart current / exception resume | 当前不在首批 host command 范围内 | 首批不把这些动作变成 Vue 壳层责任位 |
| 售前方案 / 导出 / 恢复等详情工具条动作 | 涉及外链、文件与恢复链路，验证面过宽 | 继续沿用 legacy 接线，待后续批次再单列合同 |

### 7.4 首批范围的实现形态

1. 首批接管允许采用“Vue shell + legacy island”形态，而不是要求整页一次性完全切成 Vue。
2. 若顶栏或步骤条出现需要展示但暂未进入首批 command 面的动作，应保留 legacy handler 或 legacy 子岛，不得为追求统一外观而私下重写业务语义。
3. 历史侧栏虽允许结构级接管，但其数据仍必须来自 `FE-20260411-13` 的 selector / 事件刷新机制，不得旁路读 legacy 私有状态。
4. 任何需要改动 task 语义、聊天持久化、工作区业务渲染的诉求，都必须视为超出本卡范围，转入后续批次或新任务卡。

- 首批范围仍可随实现过程临时扩大。

- 顶栏和工具条动作的 owner 未拆开，导致实现者仍需现场判断哪些动作要跟着迁移。

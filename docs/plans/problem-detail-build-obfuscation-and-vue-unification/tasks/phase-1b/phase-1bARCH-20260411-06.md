## 2. 任务目标

- 冻结 A 线 `frontend/dist` 的部署、缓存失效与整包回滚口径。
- 让部署与前端验证共享同一套合同。

## 3. 当前事实

- A 线的目标不仅是 build 出 dist，还要能部署、验证并快速回滚。
- 若没有部署与缓存合同，轻混淆和 bundle 变更上线后容易出现旧资源残留或版本错配。
- 若没有整包回滚规则，线上异常时很难快速恢复到上一个稳定版本。
- `FE-20260411-07` 已冻结 `frontend/dist` 为唯一发布目录，且当前正式入口与多数资源仍采用固定文件名，因此部署必须按“整包同批次切换”处理，不能散点覆盖。
- `frontend-vue` 现有 `vue-auth-assets/version.txt` 已提供共享资源版本指纹，可作为 A 线运行时证据的一部分；A 线自有 bundle 与 HTML / 配置也需要形成同批次版本命中口径。

### 7.1 部署目录映射合同


| 源                                                                            | 目标                       | 固定口径                      |
| ---------------------------------------------------------------------------- | ------------------------ | ------------------------- |
| `frontend/dist/`                                                             | 线上 ProblemDetail 站点部署根目录 | 以整包目录为单位发布，不拆分到多个平行部署根    |
| `frontend/dist/index.html`                                                   | 公开详情入口                   | 继续承接 `index.html?caseId=` |
| `frontend/dist/home.html` 等其他正式入口                                            | 同一部署根目录下的平级页面            | 与详情入口同批次发布，不允许落在第二根目录     |
| `frontend/dist/js/*`、`frontend/dist/css/*`、`frontend/dist/vue-auth-assets/*` | 部署根目录内对应子目录              | 与 HTML 同批次替换              |


部署原则：

1. 发布动作以“准备完整新包 -> 校验完整性 -> 原子替换部署根”完成，不允许边上传边被浏览器命中。
2. 禁止只发布 `js/`、只发布 `vue-auth-assets/` 或只发布 HTML；必须保证整包同批次切换。
3. 若部署平台无法提供原子切换或等价能力，本批次不得上线。

### 7.2 缓存失效口径


| 资源类型                                         | 缓存口径                                             | 原因                        |
| -------------------------------------------- | ------------------------------------------------ | ------------------------- |
| HTML 入口文件                                    | 不允许强缓存；必须可 revalidate / 每次请求校验新鲜度                | 固定文件名，需尽快指向当前批次资源         |
| `config.js` / `config.local.js`              | 不允许强缓存；与 HTML 同级处理                               | 环境差异和回滚依赖其即时生效            |
| `js/auth-runtime.js`                         | 不允许长时间强缓存；至少保证随批次可快速更新                           | 登录 / 门禁链路直接依赖             |
| A 线 bundle（如 `problem-detail-app.bundle.js`） | 必须与 HTML 同批次生效；若文件名固定，则部署侧需配合 revalidate 或等价失效策略 | 避免旧 HTML 命中新 JS / 旧 JS 混搭 |
| `vue-auth-assets/**`                         | 同批次替换，并以 `version.txt` 作为版本命中核验点                 | 现有 Vue 入口链使用固定文件名 + 版本指纹  |
| CDN 外链                                       | 保持外链，不纳入本仓发布缓存控制                                 | A 线只核验其可用性与命中，不负责其上游缓存    |


### 7.3 版本命中与部署完成证据


| 证据类型                   | 最低要求                                                                           |
| ---------------------- | ------------------------------------------------------------------------------ |
| 发布批次标识                 | 每次部署必须产生唯一 `release_id` 或等价发布编号，并写入运行时证据记录                                     |
| dist 完整性证据             | 部署前后至少各保留一次 `frontend/dist` 目录结构检查结果或等价清单                                      |
| `vue-auth-assets` 版本证据 | 记录 `vue-auth-assets/version.txt` 实际内容                                          |
| 浏览器命中证据                | 打开详情页 / 首页 / 登录页时，记录 HTML、bundle、`auth-runtime.js`、`vue-auth-assets/*` 的实际命中情况 |
| 配置命中证据                 | 证明浏览器命中的 `config.js` / `config.local.js` 属于本次部署批次预期环境                          |


### 7.4 整包回滚动作


| 场景                                | 默认动作                                              |
| --------------------------------- | ------------------------------------------------- |
| 上线后发现入口级错误、资源大面积 404、HTML / JS 混批 | 立即整包回滚到上一个稳定发布包                                   |
| 仅轻混淆导致运行时异常且已有“仅 minify 稳定包”      | 优先回滚到上一稳定包；是否保留同批次 build 给 `FE-20260411-10` 分级表裁决 |
| 仅配置文件错误                           | 回滚配置文件到上一个稳定版本；若无法单独确认一致性，则执行整包回滚                 |
| CDN 外链不可用                         | 不直接改包；先记录外链异常并按失败分级处理，必要时停止当前批次继续验收               |


最小动作闭环：

1. 确认命中的发布批次异常。
2. 切回上一个稳定的完整部署包。
3. 重新打开 `index.html?caseId=`、`home.html`、`login.html` 校验回退成功。
4. 在运行时证据和验收记录中补记本次回滚批次、触发原因与回退结果。

### 7.5 触发器与责任位


| 项       | 固定口径                                                           |
| ------- | -------------------------------------------------------------- |
| 发布责任位   | frontend 执行发布包准备，architect owner 审核合同口径，实际部署执行人与环境管理员按团队现有分工落地 |
| 立即回滚触发器 | 入口不可打开、静态资源大量 404、详情深链失效、登录 / 模型配置门禁失效、资源混批可见                  |
| 暂停批次触发器 | 无法确认浏览器命中版本、配置命中与部署批次不一致、整包回滚路径不可用                             |
| 继续验收前提  | 已有唯一发布批次号、完整部署包、可执行回滚包与浏览器命中证据                                 |

## 2. 任务目标

- 建立 A 线上线与验收可复用的运行时证据模板。
- 覆盖 build 版本、部署证据、浏览器命中版本与最小 smoke 结果。
- 让“已上线并验证”有统一证据格式，而不再只靠口头说明。

## 3. 当前事实

- 仅有“本地 build 成功”不足以证明上线成功。
- A 线需要同时证明构建版本、部署完成、浏览器实际命中版本与最小业务链路正常。
- 若没有统一模板，每次验收的证据粒度会不一致，难以追溯。
- `ARCH-20260411-06` 已冻结发布批次号、`vue-auth-assets/version.txt`、浏览器资源命中和整包回滚为必备证据面。
- A 线资源仍以固定文件名为主，因此运行时证据必须关注“浏览器实际命中了哪一批 HTML / JS / 配置”，而不是只看构建日志。

## 4. In Scope

- 运行时证据模板字段。
- 版本、部署、浏览器命中、smoke 结果的统一记录方式。
- 与 deploy 合同和验收记录模板的衔接。

## 5. Out Of Scope

- 真实上线执行。
- 自动化采集脚本。
- B 线 fixture / 双渲染证据。

### 7.2 字段说明

| 字段 | 最低要求 |
| --- | --- |
| `release_id` | 唯一发布批次号，不可缺失 |
| `dist 来源提交` | 至少能回到本次构建所基于的 commit |
| `vue-auth-assets/version.txt` | 必填；用于证明共享资源命中批次 |
| 浏览器命中证据 | 至少覆盖 1 个详情页、1 个首页/登录链、1 组共享资源 |
| Console 结果 | 不能只写“正常”，需说明是否有 error / warning |
| smoke 结果 | 必须按固定矩阵填写，不接受自由发挥式描述 |
| 异常与回滚 | 即使无异常，也要明确写 `no` |

### 7.3 有效证据类型

| 类型 | 可作为有效证据 | 说明 |
| --- | --- | --- |
| 命令输出 | `find frontend/dist ...`、`cat frontend/vue-auth-assets/version.txt` | 用于证明部署包完整性 |
| 浏览器 Network | HTML、bundle、配置、`auth-runtime.js`、`vue-auth-assets/*` | 用于证明实际命中 |
| 浏览器 Console | 错误 / 警告摘要 | 用于证明运行时清洁度 |
| 页面截图 | 详情页、首页、登录页、模型配置页、报告页 | 用于证明关键入口可打开 |
| smoke 记录表 | 固定矩阵执行结果 | 用于横向比较不同批次 |

## 9. 验收边界

### 9.1 完成结果

- 模板至少包含 build 版本、deploy 证据、浏览器命中版本证据、最小 smoke 结果。
- 不同执行人可按统一模板留证，后续可复查。

### 9.2 不算完成的情况

- 模板只能记录“本地 build 成功”。
- 缺少浏览器命中版本或最小 smoke 结果字段。
- 没有标准记录格式，证据仍散落在聊天里。

## 10. 必备证据

- 文档或产物文件：运行时证据模板、示例记录
- 命令或检查入口：
  - `find frontend/dist -maxdepth 3 -type f | sort`
  - `cat frontend/vue-auth-assets/version.txt`
  - 浏览器 Network / Console / Sources 检查入口
- 最小回归项：用模板覆盖详情深链、默认入口、登录 / 模型配置链、共享资源命中与最小交互链路验证结果
- 若适用则写 diff / fixture / 运行时证据：后续真实发布时按本模板补浏览器 Network/Console 截图位

## 11. 失败/停止条件

- 模板字段无法覆盖 deploy 合同要求。
- 证据格式无法记录浏览器实际命中信息。
- 与验收记录模板职责重叠且边界不清。
- 若执行人无法提供 `release_id`、`version.txt` 或浏览器命中记录三者中的任一项，不得宣称上线验证完成。

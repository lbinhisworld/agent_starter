# FE-20260411-19 · 建立 selector 对照检查清单

## 1. 任务元数据

- 任务编号：`FE-20260411-19`
- Phase：`2B`
- owner：`frontend`
- 优先级：`P0`
- 状态：`completed`

## 2. 任务目标

- 建立逻辑一致性所需的 selector 对照检查清单。
- 用固定检查点验证 Vue shell 与 legacy 在同一 fixture 输入下的状态一致性。
- 避免“逻辑一致”只停留在口头判断。

## 3. 当前事实

- UI 一致不代表逻辑一致，B 线需要先保证 selector 层输入一致。
- 若 selector 检查点不固定，双渲染很难判断差异是输入问题还是渲染问题。
- `task1` 最新链路已引入 `preliminaryReq` 新顶层结构、状态逻辑 entity 展示分组、按 entity 分桶分步合并、新 entity 直写、人员组织归并与历史详情项变化，必须进入 selector 对照。
- 首批接管范围已包含历史侧栏，而当前历史侧栏真实结构已包含任务树、汇总 token/耗时指标、详情 / 过程日志 / Skill / 审计 Skill 四类 tab 与对应 panel，不能只验入口存在。
- selector 对照是 DOM 对照之前的前置验证。

## 7. 实施说明

1. 基于 host / selector 合同定义固定的逻辑对照检查点。
2. 优先覆盖 `caseId`、当前任务、步骤条状态、聊天摘要、历史任务归档，以及历史侧栏任务树、汇总指标、激活 tab 与 panel 对应关系等关键状态。
3. 若 fixture 命中 `task1`，补充检查 `preliminaryReq` 顶层键、核心对象数量、状态逻辑 entity 分组、每个 entity bucket 的转移条数/关键转移保留、新 entity 追加结果、既有 entity 合并结果、人员组织 `stakeholders` 归并结果与历史详情数量。
4. 为每个检查点写明读取方式与通过标准。
5. 保证对照前提是同一 `fixture_id + fixture_version`。

### 7.1 对照执行总规则

| 项 | 固定口径 |
| --- | --- |
| 输入前提 | 同一轮对照只能读取同一 `fixture_id + fixture_version` |
| 读取入口 | 只允许通过 `FE-20260411-13` 冻结的 selector 读取，不旁路读 DOM、legacy 私有状态或局部变量 |
| 对照顺序 | 先做 selector 对照，selector 通过后才允许进入 DOM 对照 |
| 记录方式 | 每个检查点都要写“字段值 / 通过与否 / 差异说明”，不能只写总体感受 |

### 7.2 壳层与导航基线检查清单

| selector | 检查点 | 适用 fixture | 通过标准 |
| --- | --- | --- | --- |
| `getShellSnapshot()` | `caseId` | 全部 fixture | legacy / vue-shell 返回同一 `caseId`，且与 fixture 元数据一致 |
| `getShellSnapshot()` | `snapshotVersion`、`loadState`、`errorState` | 全部 fixture | 两侧快照版本可不同步递增，但当前对照时刻的 `loadState` / `errorState` 必须同义；空态 fixture 必须同为 `empty` 或对应受控状态 |
| `getHeaderSnapshot()` | `archiveNo`、`customerName`、`requirementTitle`、`caseHeadline` | 除纯空态外全部 fixture | 关键字段命中一致，不允许一侧缺字段或用旧标题 |
| `getTaskNavigationSnapshot()` | `currentMajorStage`、`viewingMajorStage`、`canonicalTaskId`、`viewingTaskId` | 全部 fixture | 当前任务、查看任务、大阶段必须一致 |
| `getTaskNavigationSnapshot()` | `taskSteps[]` 的顺序、状态、当前高亮 | 全部 fixture | task1-task15 顺序一致；每步状态与高亮一致，不允许跳步或回退 |
| `getLegacyMountSnapshot()` | `workspaceMountMode`、`chatMountMode`、`historyMountMode` | 全部 fixture | 首批允许区块与 legacy island 边界一致，不允许 Vue shell 偷接未授权区块 |

## 9. 验收边界

### 9.1 完成结果

- 清单至少覆盖 `caseId`、当前任务、步骤条状态、聊天摘要、历史任务归档。
- 对历史侧栏类 fixture，清单已覆盖任务树节点集合、汇总 token/耗时指标、当前激活 tab、各 tab 对应 panel 数据命中与 Skill / 审计 Skill 可见性。

- “逻辑一致”已经被拆成具体可检查的 selector 点。

### 9.2 不算完成的情况

- 只有“逻辑一致”口号，没有检查点。
- 缺少 `caseId`、当前任务或步骤条状态等关键项。
- 历史侧栏只校验入口是否能开，没有任务树、tab、汇总指标与 Skill 面板级检查点。
- `task1` fixture 仅看页面观感，没有结构化状态检查点。
- 检查项无法绑定到 fixture 输入。

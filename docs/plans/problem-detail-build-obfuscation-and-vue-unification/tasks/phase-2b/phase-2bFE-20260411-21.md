# FE-20260411-21 · 建立 legacy / vue-shell 双渲染验证流程

## 1. 任务元数据

- 任务编号：`FE-20260411-21`
- Phase：`2B`
- owner：`frontend`
- 优先级：`P0`
- 状态：`completed`

## 2. 任务目标

- 建立 `legacy` / `vue-shell` 双渲染验证流程。
- 固定同一输入、同一版本、同一检查顺序的对照步骤。
- 防止后续用在线活案例或不同输入快照做无效对照。

## 3. 当前事实

- 双渲染对照若不固定流程，差异很难追责到输入、selector 还是 DOM。
- 正式验收必须建立在同一 `fixture_id + fixture_version` 上。
- selector 与 DOM 对照都需要被纳入统一流程，不能分散执行。

## 7. 实施说明

1. 固定双渲染流程的输入前提必须是同一 `fixture_id + fixture_version`。
2. 规定执行顺序为：加载固定 fixture、先 selector 对照、再 DOM 对照、最后记录结论与差异。
3. 明确双渲染必须建立在 `FE-20260411-16` 的同 URL 技术合同之上，两侧只允许通过同一 `index.html?caseId=` 和不同 shell 选择结果渲染。
4. 明确禁止直接用在线活案例作为正式对照输入。
5. 对发现差异后的记录、回退与升级人工条件给出最小口径。

### 7.1 双渲染输入前提

| 项 | 固定口径 |
| --- | --- |
| fixture 前提 | 只能选择一张 `fixture_id + fixture_version` 开始一轮对照 |
| URL 前提 | 两侧都必须基于同一 `index.html?caseId=` 入口渲染，不允许换另一条 HTML 路径 |
| shell 前提 | 只允许通过 `FE-20260411-16` 冻结的 `legacy` / `vue` 选择结果切换，不新增第三种模式 |
| 数据前提 | 不允许在线回源补数据，不允许临时改 fixture 文件内容 |

### 7.2 固定执行步骤

| 步骤 | 动作 | 通过标准 |
| --- | --- | --- |
| 1 | 锁定单个 `fixture_id + fixture_version` | 本轮记录中明确写出 fixture 标识 |
| 2 | 以 `legacy` 方式渲染同 URL | 成功得到 legacy 基线渲染结果 |
| 3 | 按 `FE-20260411-19` 完成 selector 对照记录 | selector 检查点全部有记录 |
| 4 | 在 selector 通过前提下，按 `FE-20260411-20` 完成 DOM 对照记录 | DOM 检查点全部有记录 |
| 5 | 切到 `vue-shell` 方式，在同 URL 下渲染同一 fixture | 成功得到 vue-shell 渲染结果 |
| 6 | 对比 selector 结果 | 差异被归类为“无差异 / selector 差异 / 阻塞” |
| 7 | 仅当 selector 通过时，对比 DOM 结果 | 差异被归类为“无差异 / DOM 差异 / 阻塞” |
| 8 | 记录结论、残余风险与下一动作 | 有明确 go / hold / escalate 结论 |

### 7.3 差异归类规则

| 差异类型 | 触发信号 | 默认动作 |
| --- | --- | --- |
| 输入差异 | 不是同一 `fixture_id + fixture_version`，或执行中偷偷改了 fixture | 本轮结果无效，回到未验收 |
| selector 差异 | `FE-20260411-19` 任一必跑检查点不通过 | 停止 DOM 结论，先回到 host / fixture / contract 排查 |
| DOM 差异 | selector 已通过但 `FE-20260411-20` 任一检查点不通过 | 记录为 UI 漂移，允许继续定位 DOM / 壳层问题 |
| 运行时阻塞 | 某一侧无法在同 URL 下完成渲染、fallback 失效或挂载失败 | 记为 blocked，并升级到同 URL / readiness 相关任务 |

### 7.4 差异记录最小模板

| 字段 | 固定要求 |
| --- | --- |
| `fixture_id` / `fixture_version` | 必填 |
| `shell_mode` | `legacy` / `vue` |
| `selector_result` | `pass` / `fail` / `blocked` |
| `dom_result` | `pass` / `fail` / `blocked` / `not_run` |
| `diff_summary` | 只写本轮关键差异，不写聊天式描述 |
| `owner_guess` | `fixture` / `host` / `vue-shell` / `legacy-shell` / `unknown` |
| `next_action` | `fix` / `new_task` / `escalate` |

### 7.5 明确禁止项

1. 禁止拿在线活案例、浏览器当前随机状态或手工改数据结果充当正式对照输入。
2. 禁止 selector 未通过就直接宣称 DOM 通过。
3. 禁止在同一轮对照里一边看 `legacy`，一边把 `vue-shell` 换成另一条页面入口。
4. 禁止把 fallback 失败、mount 失败、同 URL 不成立等技术问题伪装成“只是视觉差异”。

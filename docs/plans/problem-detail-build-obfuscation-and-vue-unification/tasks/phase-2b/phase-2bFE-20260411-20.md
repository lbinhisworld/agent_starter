# FE-20260411-20 · 建立 DOM 对照检查清单

## 2. 任务目标

- 建立 UI 一致性所需的 DOM 对照检查清单。
- 用固定检查点验证 Vue shell 与 legacy 的可见结构和交互显隐一致。
- 避免“UI 一致”只凭主观观感判断。

## 3. 当前事实

- B 线的目标之一是保证 UI 完全一致，但 UI 一致必须拆成具体 DOM 检查点。
- 若没有 DOM 对照清单，后续很难判断差异是允许偏差还是不可接受漂移。
- `task1` 最新工作区已新增 `view/json/历史详情` 切换、核心对象卡、状态逻辑按 entity 折叠子卡、逐条转移摘要、状态逻辑图卡、`+需求` 与历史详情删除等结构，不补检查点就会漏漂移。
- 首批接管范围中的历史侧栏当前已包含顶部汇总指标、任务树、详情 / 过程日志 / Skill / 审计 Skill 四个 tab 与对应面板，已不是只看入口按钮的复杂度。
- DOM 对照需要建立在 selector 对照已通过的基础上。

## 7. 实施说明

1. 基于首批接管范围，定义 UI 对照必须关注的 DOM 检查点。
2. 至少覆盖标题、按钮顺序、显隐、错误态、loading，以及历史侧栏的汇总区、任务树、四个 tab 与对应 panel 结构。
3. 若 fixture 命中 `task1` 工作区，补充检查 `view/json/历史详情` 切换、核心对象卡、状态逻辑 entity 折叠子卡标题与条数、逐条转移摘要列表、状态逻辑图卡与全屏按钮、`+需求` 入口与历史详情删除按钮。
4. 若 fixture 命中历史侧栏，补充检查任务节点展开、tab 顺序、详情/过程日志/Skill/审计 Skill 面板显隐切换，以及顶部汇总指标块存在与顺序。
5. 为每个检查项给出“通过 / 不通过”的最小判断规则。
6. 明确 DOM 对照必须建立在同一 fixture 与 selector 对照已通过的前提上。

### 7.1 对照执行总规则

| 项 | 固定口径 |
| --- | --- |
| 前置门 | 同一 fixture 的 selector 对照必须已通过 |
| 输入前提 | 只能对比同一 `fixture_id + fixture_version` 渲染出的 DOM |
| 检查原则 | 先看结构，再看顺序，再看显隐；不先凭“看起来差不多”下结论 |
| 记录方式 | 每项都要给出“通过 / 不通过 / 差异说明”，不写模糊评价 |

### 7.2 壳层与导航 DOM 检查清单

| 检查项 | 必须命中的 fixture | 通过标准 |
| --- | --- | --- |
| 顶栏主区域存在性 | 全部 fixture | 顶部壳层存在，不缺主容器 |
| 返回 / 案例编号 / 重置 / 沟通历史等按钮顺序 | `pd-online-shell-new-case-empty`、`pd-online-workflow-align-active`、`pd-online-task10-role-permission-modify` | 核心按钮顺序一致，不发生错位或缺失 |
| 模型配置 / 退出登录等导航入口显隐 | 同上 | 显隐规则一致，不一边显示一边缺失 |
| 案例标题 / headline 容器 | 除纯空态外全部 fixture | 标题容器存在且层级一致 |
| loading / error / empty 壳层 | `pd-online-shell-new-case-empty` 及必要错误态 fixture | 壳层状态区存在性、占位位置与切换行为一致 |

### 9.2 不算完成的情况

- 没有具体检查项。

- 历史侧栏仍只检查入口，不检查任务树、tab、汇总指标与面板结构。
- `task1` 新增工作区结构未被纳入 DOM 检查。
- DOM 对照不依赖固定 fixture 或 selector 前置通过。

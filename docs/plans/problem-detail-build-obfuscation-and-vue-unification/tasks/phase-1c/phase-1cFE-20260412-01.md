# FE-20260412-01 · 实现 frontend dist build runner

## 1. 任务元数据

- 任务编号：`FE-20260412-01`
- Phase：`1C`
- owner：`frontend`
- 优先级：`P0`
- 状态：`completed`

## 2. 任务目标

- 把 Phase 1A 已冻结的 build 输入输出合同真正落成可执行的旧 `frontend` build runner。
- 让执行者可以稳定产出 `frontend/dist`，不再依赖手工拷贝与口头约定。
- 为后续 minify / 轻混淆 / smoke 提供唯一执行入口。

## 3. 当前事实

- `FE-20260411-02`、`FE-20260411-03`、`FE-20260411-07` 已冻结 build 输入、脚本顺序与 dist 目录口径，但还没有真正的 runner 落地。
- 旧 `frontend/` 仍以静态 HTML + 顺序脚本为主，不能用“改成另一套公开入口”的方式偷换 build 成功。
- 若 build runner 不先固化，后续 minify、light obfuscation 与 smoke 会缺少统一产物基线。

## 4. In Scope

- 选择并落地旧 `frontend` 的 build runner 入口。
- 将 bundle、copy、external 三类产出收口到 `frontend/dist`。
- 明确可重复执行的命令、输入目录、输出目录与失败时退出口径。

## 5. Out Of Scope

- 轻混淆参数调优。
- 生产部署脚本。
- Vue detail shell 或 B 线迁移实现。

## 6. 前置依赖

- `FE-20260411-02`
- `FE-20260411-03`
- `FE-20260411-07`

## 7. 实施说明

1. 已以 `FE-20260411-02` 的输入输出合同为唯一真相源，在 [frontend/scripts/build-dist.mjs](/Users/tzknow/Documents/do1/workspace/do1_smart_cto/frontend/scripts/build-dist.mjs) 落地旧 `frontend` build runner。

5. 当前固定执行入口为 `node frontend/scripts/build-dist.mjs`，失败时直接非零退出。

## 9. 验收边界

### 9.1 完成结果

- 能通过固定命令稳定生成 `frontend/dist`。
- `frontend/dist` 同时包含入口 HTML、legacy/runtime 产物、外置配置与 `vue-auth-assets/**`。
- 实现者不需要再手工判断哪些文件要复制、哪些要参与产物链。

### 9.2 不算完成的情况

- 只有零散脚本，没有统一 runner 入口。
- 只打出详情页面，漏掉首页、登录、模型配置、报告等公开入口。
- 仍需人工拷贝关键文件才能形成可部署目录。

## 10. 必备证据

- 文档或产物文件：runner 入口、`frontend/dist` 目录快照、最小使用说明
- 命令或检查入口：固定 build 命令 + `find frontend/dist -maxdepth 3 -type f | sort`
- 最小回归项：build 后能解释 `index.html`、`home.html`、`login.html`、`model-config.html`、`report.html` 与 `vue-auth-assets/**` 的去向
- 若适用则写 diff / fixture / 运行时证据：执行日志与 dist 目录对照

## 11. 失败/停止条件

- runner 需要引入第二公开入口或改写既有 URL 才能工作。
- 无法在不破坏脚本顺序合同的前提下输出 dist。
- build 输入输出与 Phase 1A 合同发生冲突且无法在当前卡内收口。

## 7. 实施说明

1. 已在 [build-dist.mjs](/Users/tzknow/Documents/do1/workspace/do1_smart_cto/frontend/scripts/build-dist.mjs) 中把 minify 接入到 `frontend/dist` 生成链，默认执行 `node frontend/scripts/build-dist.mjs` 即生成压缩产物；`--no-minify` 作为压缩前对照入口保留。
2. JS minify 当前仅作用于 `problem-detail-app.bundle.js`、`home-legacy.bundle.js`、`report-app.bundle.js` 三个 A 线生成 bundle，未扩散到 `config.js`、`config.local.js`、`js/config.js`、`js/auth-runtime.js` 与 `vue-auth-assets/**`。
3. HTML minify 作用于 `index/home/login/admin/model-config/report.html` 六个正式入口，保留入口脚本顺序，仅压缩结构空白、移除注释并压缩内联 bootstrap / helper script。
4. CSS minify 当前仅作用于 `styles.css` 与 `css/report.css`，不触碰 `vue-auth-assets/*.css`，避免把 `frontend-vue` 产物链混入 A 线压缩范围。
5. JS 压缩复用了 `frontend-vue` 已安装工具链中的 `@babel/parser` + `@babel/generator` 做保守 AST 压缩，CSS 压缩复用 `lightningcss`；若工具链缺失，runner 会明确提示先在 `frontend-vue` 执行 `npm ci`。

## 9. 验收边界

### 9.1 完成结果

- `frontend/dist` 产物在不改公开行为的前提下完成 js/html/css minify。
- 压缩前后关键入口、脚本顺序与保留名口径一致。
- 后续 obfuscation 可以明确建立在 minify 之后的稳定基线上。

### 9.2 不算完成的情况

- 压缩收益与行为漂移混在一起，无法说明边界。
- 通过修改入口 HTML、删减资源或改写外置配置来“伪装”压缩成功。
- 没有最小对照证据，无法判断问题出在 minify 还是 build runner。

## 10. 必备证据

- 文档或产物文件：minify 配置、保留面说明、压缩前后体积对照
- 命令或检查入口：固定 build/minify 命令、关键 HTML/JS 产物抽样比对
- 最小回归项：入口 HTML 可打开、脚本顺序未漂、关键全局名可用
- 若适用则写 diff / fixture / 运行时证据：压缩前后 smoke 抽样结果

## 11. 失败/停止条件

- minify 破坏 `index.html` 脚本顺序或入口跳转链。
- 需要改写 Phase 1A 明确要求保留的全局名或字符串字面量。
- 无法把压缩问题与混淆问题分开定位。

# FE-20260412-03 · 接入 light obfuscation with keep list

## 1. 任务元数据

- 任务编号：`FE-20260412-03`
- Phase：`1C`
- owner：`frontend`
- 优先级：`P0`
- 状态：`completed`

## 2. 任务目标

- 在 minify 已稳定的基础上，为 A 线接入可控的 light obfuscation。
- 严格以 keep list / 白名单为前提，提高阅读成本但不破坏运行时合同。
- 给生产发布提供“有限保护 + 可回滚”的实际执行方案。

## 3. 当前事实

- `FE-20260411-04` 已冻结轻混淆允许项与禁止项，`FE-20260411-05` 已冻结保留名 / 白名单合同。
- 旧 `frontend` 大量依赖全局桥接、URL 参数、storage key、DOM/data 反射与消息字面量，不能套默认高强度混淆配置。
- 当前专项的目标是工程化落地，不是以混淆代替架构统一。

## 4. In Scope

- light obfuscation 配置接入。
- keep list / 保留名消费方式与校验方式。
- 出问题时快速关闭 obfuscation 的回退口径。

## 5. Out Of Scope

- 高强度混淆策略试验。
- anti-debug/self-defending/control-flow flattening 等高风险手段。
- B 线 host / shell 实现。

## 6. 前置依赖

- `FE-20260411-04`
- `FE-20260411-05`
- `FE-20260412-02`

## 7. 实施说明

1. 已在 [build-dist.mjs](/Users/tzknow/Documents/do1/workspace/do1_smart_cto/frontend/scripts/build-dist.mjs) 中把 light obfuscation 接到 minify 之后，仅作用于 `problem-detail-app.bundle.js`、`home-legacy.bundle.js`、`report-app.bundle.js` 三个 legacy bundle。
2. 实现方式固定为 `terser` 的顶层标识符改名：关闭 `compress`、不启用 property mangling、不改字符串字面量、不引入任何 control-flow flattening / self-defending / dead-code injection / debug protection。
3. keep list 已通过 `lightObfuscationReservedIdentifiers` 显式接入，首批覆盖 `SmartCto`、`APP_CONFIG`、公开 bridge 标识符、compat 双挂函数名与运行时全局宿主名；storage key、URL 参数、`message.type`、DOM/data 契约则通过“禁止 property / string 改写”自然保留。
4. 已把 `--no-obfuscation` 作为独立降级开关，异常时可直接回到“仅 minify”构建，不需要回滚整条 build 链。
5. 为保证依赖显式可追踪，已把 `terser` 固化到 [frontend-vue/package.json](/Users/tzknow/Documents/do1/workspace/do1_smart_cto/frontend-vue/package.json) 的 `devDependencies`。

## 9. 验收边界

### 9.1 完成结果

- 旧 `frontend` 产物可在 minify 之后稳定接入 light obfuscation。
- 保留名 / 白名单被明确消费，关键全局桥接、URL 参数、storage key、DOM/data 与消息字面量未被破坏。
- 出现问题时可以快速降级回“仅 minify”。

### 9.2 不算完成的情况

- 使用高强度混淆配置或引入禁止项。
- keep list 只是口头说明，没有真正接入执行链。
- 一旦出问题只能整条 build 链回滚，无法单独关闭 obfuscation。

- 最小回归项：`SmartCto.*`、`caseId` / `view`、storage key、消息类型与关键 DOM/data 契约在运行时仍可用

- obfuscation 开关无法独立于 minify 回退。

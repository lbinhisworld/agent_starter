# FE-20260411-05 · 建立混淆白名单 / 保留名合同

## 1. 任务元数据

- 任务编号：`FE-20260411-05`
- Phase：`1A`
- owner：`frontend`
- 优先级：`P0`
- 状态：`completed`

## 2. 任务目标

- 建立轻混淆场景下必须保留的命名与白名单合同。
- 覆盖运行时桥接、反射、DOM 约定、URL 参数与存储约定。
- 避免混淆后出现公开契约漂移。

## 3. 当前事实

- ProblemDetail 同时依赖全局对象、storage key、message type、URL 参数、DOM `data-*` 约定。
- 浏览器端代码中可能存在字符串反射、HTML 直连脚本和 bridge 读取。
- 若没有保留名合同，轻混淆也足以破坏运行时链路。
- 已确认保留项不止 `SmartCto.*`，还包括 `window.APP_CONFIG`、compat 双挂、`caseId` / `view` 路由参数、滚动恢复 / 子步骤 session key 前缀与 ProblemDetail 聊天 `type` 字面量。
- `message.type` 当前已形成稳定业务协议面；即便字段名不改，只要字面量被改写，也会破坏 hydrate、去重、步骤判断与历史侧栏渲染。

## 4. In Scope

- `SmartCto.*`、storage key、message type、DOM / `data-*`、URL 参数、反射相关名字。
- 与 ProblemDetail 对外语义相关的保留项。
- 对“允许缩写 / 不允许改名”的说明。

## 5. Out Of Scope

- 轻混淆策略强度选择。
- 第三方 vendor 代码内部命名。
- 新增业务协议或新公开 API。

## 6. 前置依赖

- `FE-20260411-03`
- `FE-20260411-04`

## 7. 实施说明

1. 已基于 `FE-20260411-03` 的桥接清单与 `frontend` 代码扫描，整理出全局名、storage、URL、DOM、`message.type` 五类保留项。
2. 已把“绝对保留”和“语义保留”拆开，避免实现时把所有字符串都一刀切。

4. 已把最容易遗漏的 `message.type` 家族、session key 前缀和 `data-*` 选择器约定写成可直接引用的合同。

| 参数 / 值 | 保留规则 |

规则补充：

- 所有 `.problem-detail-*`、`.btn-*`、`.tools-*` 这类被 JS 查询或事件代理依赖的 class / `data-*` 均属于语义保留面，不得在轻混淆或 bundle 阶段改名。
- 不要求把普通局部变量名都加入白名单，但凡出现在 `querySelector`、`closest`、`dataset.*`、`getAttribute('data-*')` 的字符串都视为保留项。

### 7.6 允许缩写 / 不允许改名边界

| 类别 | 规则 |
| --- | --- |
| 绝对不允许改名 | 上述全局桥接、storage key、session key 前缀、URL 参数、DOM / `data-*` 契约、`message.type` 字面量 |

## 9. 验收边界

### 9.1 完成结果

- 白名单必须覆盖 `SmartCto.*`、storage key、message type、DOM / `data-*` 约定、URL 参数与反射相关名字。
- 实现者能够据此直接配置保留项，而不是凭经验猜测。

### 9.2 不算完成的情况

- 只有泛泛描述，没有明确名单。
- 漏掉 storage key、message type、URL 参数或 DOM 约定中的任一类。
- 仍允许实现阶段临时追加关键保留名。

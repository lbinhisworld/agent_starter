# FE-20260411-03 · 冻结脚本顺序、模块依赖与全局桥接保留规则

## 1. 任务元数据

- 任务编号：`FE-20260411-03`
- Phase：`1A`
- owner：`frontend`
- 优先级：`P0`
- 状态：`completed`

## 2. 任务目标

- 冻结旧 `frontend` 的脚本加载顺序与模块依赖关系。
- 固定 `main.js`、runtime、HTML 直连脚本与桥接对象的保留规则。
- 避免 build/minify 后出现顺序错乱或桥接丢失。

## 3. 当前事实

- 旧 `frontend` 不是完全模块化工程，仍有顺序依赖和全局桥接。
- ProblemDetail 运行依赖 `main.js`、`problem-detail-runtime`、`problem-detail-chat` 与若干 legacy/core 桥接协同。
- 若未显式冻结顺序和暴露名，压缩与 bundle 容易造成运行时断链。
- `problem-detail-runtime.js` 明确要求自身在 `main.js` 之前完成挂载，否则 `main.js` 会直接抛错。
- `main.js` 末尾 bootstrap 还存在一层内部硬顺序：`task8GlobalItGap.init` / `initTask2CompanionRuntime` -> `problemDetailRenderer.init` -> `problemDetailChat.init` -> `initProblemDetailRuntime(__host)` -> `problemDetailEvents.install`。

## 4. In Scope

- 脚本顺序、模块依赖、桥接对象暴露规则。
- `main.js`、`problem-detail-runtime`、`SmartCto.*`、HTML 直连脚本的保留说明。
- 对“可重排 / 不可重排”的最小边界说明。

## 5. Out Of Scope

- 混淆工具配置本身。
- 改写 runtime 或 `main.js` 逻辑。
- dist 拷贝目录细节。

### 7.1 `index.html` 加载顺序冻结表

| 顺序层 | 必须先于谁 | 代表文件 | 冻结规则 |
| --- | --- | --- | --- |
| 入口内联 redirect | 所有业务脚本 | `index.html` 顶部 redirect script | 必须最先执行，继续保留 `caseId` / `view=tools` 分流与无参数跳 `home.html` |
| 外置配置 | `js/config.js`、`main.js`、所有读取 `APP_CONFIG` 的脚本 | `config.js`、`config.local.js` | 必须先于任何读取 `window.APP_CONFIG` 的逻辑 |
| 基础同步工具脚本 | legacy 业务同步脚本、模块 bootstrap、`main.js` | `js/config.js`、`js/utils.js`、`js/auth-runtime.js` | 保持早于业务脚本与模块初始化 |
| legacy 业务同步脚本 | 模块 bootstrap、`main.js` | `js/api.js`、`js/storage*.js`、`js/task*.js`、`js/rendering.js`、`js/navigation.js`、`js/rolePermission.js`、`js/coreBusinessObject.js` | 允许打进 bundle，但相对初始化依赖不能缺失 |
| 核心模块脚本 | `main.js` | `js/core/problem-case-api.js`、`app-state.js`、`js/legacy/app-dom.js`、`problem-detail-renderer.js`、`problem-detail-events.js`、`problem-detail-chat.js`、`problem-detail-runtime.js`、`task2-companion-runtime.js`、`task8-global-itgap.js` | 必须整体早于 `main.js`；若拆包，仍要保证在 `main.js` 启动前完成挂载 |
| 同步桥接脚本 | `main.js` | `js/core/problem-follow-shared.js` | 必须在 `main.js` 顶部 bridge 解构前完成挂载 |
| defer 尾部脚本 | 无；其自身按 HTML 声明顺序 | `js/flow-exception-record.js`、`js/it-design-bpm-flow-render.js`、`js/itDesignSupplement.js`、`main.js` | `main.js` 必须仍是尾部最终装配脚本；前 3 个若并入 bundle，需保证 `main.js` 使用点已具备 |

### 7.2 `main.js` bootstrap 内部硬顺序

| 顺序 | 调用点 | 不能换位的原因 |
| --- | --- | --- |
| 1 | `SmartCto.task8GlobalItGap.init(...)` | `task8` runtime 先完成 host 注入，后续 UI / task 编排会立即委托它 |
| 2 | `SmartCto.initTask2CompanionRuntime(...)` | `renderer` 初始化后会读取 `isInBmcDiscussionMode` 等 task2 能力 |
| 3 | `SmartCto.problemDetailRenderer.init(...)` | 需要在 host 装配与事件安装前先具备纯展示更新器 |
| 4 | `problemDetailChatBridge.init(...)` | `problemDetailRuntime` host 会引用 chat 能力；不能晚于 host 挂载 |
| 5 | `__ensureProblemDetailRuntimeHostMounted()` | `problemDetailRuntime` 的 `__host` 依赖 renderer/chat 已就绪，且必须早于 events 安装 |
| 6 | `installGlobalFlowExceptionCapturers()` | 异常探针要在事件全面工作前就位 |
| 7 | `SmartCto.problemDetailEvents.install(...)` | 事件绑定依赖前面的 renderer/chat/runtime host 全部可用 |
| 8 | `window.renderProblemDetailContent` / `window.handleProblemDetailChatSend` 等兼容双挂 | 仅作为兼容桥接暴露，不能替代 `SmartCto.*` 真相源 |

### 7.3 模块依赖与桥接真相源

| 模块 / 全局 | 直接依赖 | 输出 / 暴露 | 保留规则 |
| --- | --- | --- | --- |
| `SmartCto.problemFollowShared` | 无 | 首页案例键 / session 共享桥 | 必须在 `main.js` 顶部 bridge 解构前可读 |
| `SmartCto.appState` | `window.APP_CONFIG`、storage hydration 标记、部分 `main.js` 后挂函数 | 详情状态 façade | 暴露名与核心 getter / setter 不能漂移 |
| `SmartCto.appDom` | 首屏 DOM | DOM 节点与选择器缓存 | `main.js` 顶部直接解构 `el`，暴露名必须保留 |
| `SmartCto.problemCaseApi` | 配置与鉴权基础脚本 | online bundle refresh / task action API | API facade 名称必须保留 |
| `SmartCto.problemDetailChat` | `SmartCto.appState` + `main.js` 注入 deps | 聊天 push/save/dedup 能力 | `main.js` 启动与运行时都直接调用 |
| `SmartCto.problemDetailRuntime` | `__host` 由 `main.js` 注入 | render/send 工作区运行时 | 必须先挂载模块本身，再由 `main.js` 注入 host |
| `SmartCto.task2Runtime` / `SmartCto.initTask2CompanionRuntime` | `main.js` 注入 deps | task2 讨论 runtime | init 导出名与 runtime 暴露名均需保留 |
| `SmartCto.task8GlobalItGap` | `main.js` 注入 deps | task8 runtime | `init` 调用点必须保留 |
| `SmartCto.problemDetailRenderer` | `SmartCto.appState` + `main.js` 注入 deps | 步骤条/顶栏/聊天 header 展示更新 | `init` 与更新方法暴露名需保留 |
| `SmartCto.problemDetailEvents` | `SmartCto.appDom.el` + `main.js` handlers | 详情 DOM 事件注册 | `install` 暴露名需保留 |
| `SmartCto.flowExceptionRecord` | 无 | 异常记录与最近动作探针 | `main.js` 多处直接调用，可视为硬保留桥 |

### 7.4 必须保留的全局桥接规则

| 类型 | 必须保留项 | 说明 |
| --- | --- | --- |
| 命名空间 | `globalThis.SmartCto` | 禁止改成新命名空间或只保留局部变量 |
| 配置根对象 | `window.APP_CONFIG` | 多页与多脚本共享入口，必须持续可直读 |
| runtime 真相源 | `SmartCto.problemDetailRuntime`、`SmartCto.problemDetailChat`、`SmartCto.appState`、`SmartCto.problemCaseApi` | 这些名称后续还将进入白名单合同 |
| renderer / events | `SmartCto.problemDetailRenderer`、`SmartCto.problemDetailEvents`、`SmartCto.appDom` | legacy 壳层桥接不可删 |
| task companion | `SmartCto.task2Runtime`、`SmartCto.initTask2CompanionRuntime`、`SmartCto.task8GlobalItGap` | 首批仍属正式运行链 |
| compat 双挂 | `window.renderProblemDetailContent`、`window.handleProblemDetailChatSend`、`window.appendProblemDetailChatMessage`、`window.pushAndSaveProblemDetailChat`、`window.recordFlowExceptionTyped`、`window.applyFlowExceptionResume`、`window.pushLlmRetryNoticeBlock` | 当前仍有 legacy/task 模块依赖，首批不能移除 |
| HTML 直连脚本入口 | `config.js`、`config.local.js`、`js/auth-runtime.js`、`js/core/problem-follow-shared.js` | 保持入口级独立脚本身份，不能无说明消失 |

### 7.5 可重排 / 不可重排边界

| 类别 | 规则 |
| --- | --- |
| 不可重排 | `config.js` / `config.local.js` 必须早于读取配置的脚本；`problem-follow-shared.js`、所有 `SmartCto.*` 核心模块必须早于 `main.js`；`main.js` bootstrap 内部 1~7 步不得换位 |
| 有条件可重排 | legacy 同步业务脚本可在 bundle 内部重组，但不得破坏其对配置、存储适配器、`SmartCto.*` 模块的初始化前提 |
| 不可删除 | `SmartCto.*` 暴露面、`window.APP_CONFIG`、compat 双挂、HTML 直连入口脚本 |
| 可延后到后续任务再定 | 具体 bundle 切片方式、vendor 是否内联、轻混淆粒度 |

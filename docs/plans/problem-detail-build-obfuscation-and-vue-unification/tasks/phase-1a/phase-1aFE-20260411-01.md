# FE-20260411-01 · 盘点旧 frontend 资产、脚本顺序与全局桥接点

## 1. 任务元数据

- 任务编号：`FE-20260411-01`
- Phase：`1A`
- owner：`frontend`
- 优先级：`P0`
- 状态：`completed`

## 2. 任务目标

- 盘点旧 `frontend` 的入口页、脚本、样式、外链与模块边界。
- 明确详情页运行所依赖的脚本加载顺序、桥接对象与 HTML 直连关系。
- 为后续 build 合同、轻混淆白名单与 dist 目录冻结提供事实底稿。

## 3. 当前事实

- 旧 `frontend` 仍以静态 HTML + 顺序脚本加载为主。
- ProblemDetail 详情链路依赖 `index.html`、`main.js` 与若干 `js/core`、`js/legacy` 模块协同工作。
- 若没有资产清单，后续 build 与混淆阶段容易遗漏全局名、漏掉 HTML 直连脚本或误改加载顺序。
- 当前公开入口至少包含 `index.html`、`home.html`、`login.html`、`admin.html`、`model-config.html`、`report.html`；其中详情主链仍固定为 `index.html?caseId=`。
- `frontend/index.html` 存在明显三段式加载链：同步非模块脚本、按顺序执行的 `type="module"` 核心模块、以及依赖前两段结果的 `defer main.js` 收尾脚本。
- `SmartCto.*` 真正的桥接挂载分散在 `js/core/*`、`js/legacy/*`、`js/flow-exception-record.js` 与 `main.js` 初始化段，不能只按单文件理解。

## 4. In Scope

- `frontend/` 下入口 HTML、JS、CSS、静态资源、配置文件、vendor 依赖盘点。
- 脚本加载顺序、module / non-module 边界、全局桥接对象清单。
- ProblemDetail 对外入口与 HTML 直连脚本关系梳理。

## 5. Out Of Scope

- 实际改造 `frontend` 构建链。
- 调整 ProblemDetail 业务逻辑或页面结构。
- 设计混淆策略本身。

### 7.2 ProblemDetail 详情主链加载顺序

| 顺序层 | 代表文件 | 作用 | 后续 build 判断 |
| --- | --- | --- | --- |
| 内联同步脚本 | `index.html` 顶部 redirect script | 无 `caseId` 时跳 `home.html`，保留深链与 tools 入口 | 必须保留为入口级逻辑，不可无脑下沉 |
| 外链 CDN | `marked`、`dompurify`、`mermaid` | Markdown、清洗、流程图渲染 | 默认保持外链或单独 vendor 策略，不在本卡定夺 |
| 配置与基础同步脚本 | `config.js`、`config.local.js`、`js/config.js`、`js/utils.js`、`js/auth-runtime.js` | 配置、工具、鉴权基础能力 | 配置偏外置；工具脚本是 bundle 候选，但顺序需冻结 |
| 旧业务同步脚本 | `js/api.js`、`js/storage*.js`、`js/task*.js`、`js/rendering.js`、`js/navigation.js`、`js/rolePermission.js`、`js/coreBusinessObject.js` | legacy 页面与任务逻辑底座 | 属于 A 线重点盘点对象，后续需区分 bundle 与 copy |
| 核心模块脚本 | `js/core/problem-case-api.js`、`app-state.js`、`problem-detail-chat.js`、`problem-detail-runtime.js`、`task2-companion-runtime.js`、`task8-global-itgap.js`、`js/legacy/app-dom.js`、`problem-detail-renderer.js`、`problem-detail-events.js` | 挂载 `SmartCto.*`、提供详情 runtime / renderer / events / state | 明确属于模块边界，顺序和暴露名必须冻结 |
| 同步桥接脚本 | `js/core/problem-follow-shared.js` | 为后续 `main.js` 提供首页案例键、session 与共享工具桥 | 必须早于 `main.js`，是顺序冻结点 |
| defer 尾部脚本 | `js/flow-exception-record.js`、`js/it-design-bpm-flow-render.js`、`js/itDesignSupplement.js`、`main.js` | 在 DOM 完成后拼装 ProblemDetail 详情行为与收尾初始化 | `main.js` 为详情总装脚本，必须晚于前置桥接与模块 |

### 7.4 `SmartCto.*` 与关键桥接对象盘点

| 全局名 | 挂载位置 | 当前职责 | 风险提示 |
| --- | --- | --- | --- |
| `SmartCto.problemCaseApi` | `frontend/js/core/problem-case-api.js` | online case API 访问、bundle refresh、task action、import/export/restore | API 路径与方法不得漂移 |
| `SmartCto.appState` | `frontend/js/core/app-state.js` | ProblemDetail 当前 item、messages、hydration 与 UI 状态真相源 | 混淆/重构不可破坏字段入口 |
| `SmartCto.appDom` | `frontend/js/legacy/app-dom.js` | DOM 选择器与节点引用收口 | 详情壳层仍依赖其节点映射 |
| `SmartCto.problemDetailRenderer` | `frontend/js/legacy/problem-detail-renderer.js` | 步骤条、顶栏、聊天标签等 renderer | UI 一致性关键桥接 |
| `SmartCto.problemDetailEvents` | `frontend/js/legacy/problem-detail-events.js` | 详情页事件绑定与交互线 | 若顺序错位，事件会整体失效 |
| `SmartCto.problemDetailChat` | `frontend/js/core/problem-detail-chat.js` | 聊天去重、消息协作、ProblemDetail chat runtime | `main.js` 直接消费 |
| `SmartCto.problemDetailRuntime` | `frontend/js/core/problem-detail-runtime.js` | 详情工作区 runtime 与 host 注入接口 | `main.js` 明确要求其先于自身加载 |
| `SmartCto.task2Runtime` / `SmartCto.initTask2CompanionRuntime` | `frontend/js/core/task2-companion-runtime.js` | task2 讨论与 companion runtime | 与详情 chat/runtime 串联 |
| `SmartCto.task8GlobalItGap` | `frontend/js/core/task8-global-itgap.js` | task8 全局 IT Gap 运行时 | 报告页与详情页都依赖 |
| `SmartCto.problemFollowShared` | `frontend/js/core/problem-follow-shared.js` | 首页案例键/session 高亮共享桥 | 明确要求早于 `main.js` |
| `SmartCto.flowExceptionRecord` | `frontend/js/flow-exception-record.js` | 流程异常快照、最近系统动作探针 | 影响异常继续与回放口径 |
| `window.APP_CONFIG` | `frontend/config.js` / `config.local.js` | 环境配置根对象 | 外置合同保留项 |

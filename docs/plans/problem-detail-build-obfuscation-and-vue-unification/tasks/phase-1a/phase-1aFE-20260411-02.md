# FE-20260411-02 · 冻结旧 frontend build 输入/输出合同

## 1. 任务元数据

- 任务编号：`FE-20260411-02`
- Phase：`1A`
- owner：`frontend`
- 优先级：`P0`
- 状态：`completed`

## 2. 任务目标

- 明确旧 `frontend` 哪些文件作为 build 输入、哪些文件原样复制、哪些资源保持外置。
- 冻结输出目录为 `frontend/dist` 的结构口径。
- 让实现者无需再自行判断“哪些文件应该打包”。

## 3. 当前事实

- 旧 `frontend` 当前缺少正式 build 工程。
- 页面、配置、脚本与静态资源混合在同一目录树下，天然存在“全量搬运”与“定向 bundle”的边界问题。
- 若 build 输入输出合同不冻结，打包结果容易出现漏文件、错入口或部署结构漂移。
- `frontend-vue` 当前会直接把 `home/login/admin/model-config` 及 `vue-auth-assets/*` 产物写入 `frontend/`，因此 A 线不能把这些页面误判为“可删除旧物”。
- A 线当前最稳口径不是“把 `frontend/` 全量打成一个新站点”，而是“保持现有公开拓扑不变，在 `frontend/dist` 内重建可部署产物集合”。

## 4. In Scope

- build 输入清单、输出清单、原样复制清单、bundle 参与清单。
- `frontend/dist` 作为唯一输出目录的约定。
- 输出目录与公开入口页的关系说明。

## 5. Out Of Scope

- 具体构建工具选型实现。
- 部署平台细节与缓存配置。
- 混淆白名单细节。

### 7.3 原样复制 / 保持外置合同


| 文件类型                            | 最低合同                                                                                                            |
| ------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| HTML 入口文件                       | 输出时仍保留 `index.html`、`home.html`、`login.html`、`admin.html`、`model-config.html`、`report.html` 这些同名入口，不能改成新的公开 URL |
| `config.js` / `config.local.js` | 原样复制到 `frontend/dist` 根目录；禁止打包进业务 bundle；部署环境继续通过替换外置配置生效                                                       |
| `js/config.js`                  | 原样复制到 `frontend/dist/js/config.js`；保持入口级直连脚本形态，不并入 legacy bundle                                                  |
| `styles.css`、`css/report.css`   | 原样复制；是否做后续样式合并不在本卡决策                                                                                            |
| `vue-auth-assets/**`            | 作为已有发布资源整体复制；不能只复制 HTML 而漏掉其 JS/CSS/shared 依赖                                                                   |
| `js/auth-runtime.js`            | 原样复制，继续作为登录、管理、模型配置等页面直连脚本                                                                                      |
| CDN 外链                          | HTML 内保持外链引用，不在本卡改成本地 vendor 文件                                                                                 |


### 7.4 `frontend/dist` 输出原则

1. `frontend/dist` 是 A 线唯一输出目录；任何构建产物、复制文件、配置文件都不得落到第二个并行部署根目录。
2. `frontend/dist/index.html` 继续承接 `index.html?caseId=` 详情深链；无 `caseId` 时仍应跳转 `home.html`。
3. `frontend/dist` 根目录必须能直接看到所有正式入口 HTML 与外置配置，不要求部署方再从其它目录拼装页面。
4. 需要进入 bundle 的 legacy JS 统一作为 A 线生成产物输出到 `frontend/dist` 内部约定位置；具体目录命名由 `FE-20260411-07` 细化，但不得改变根入口与外置配置口径。
5. `frontend-vue` 已经产出的 `home/login/admin/model-config` 页面及 `vue-auth-assets/**` 在 A 线视角属于“现状产物输入”，先保证可部署复制，不在本卡引入二次构建职责。

### 7.5 单项判定规则


| 场景                                       | 固定判定                   |
| ---------------------------------------- | ---------------------- |
| 文件被 HTML 直接以 `<script src>` 引用，且承载部署环境差异 | 默认保持外置或原样复制，先不并 bundle |
| 文件是 ProblemDetail legacy/runtime 主链 JS   | 默认进入 A 线 bundle 范围     |
| 文件来自 `frontend-vue` 构建产物目录               | A 线只复制，不负责重新产出         |
| 文件仅为文档说明、设计草稿、非发布素材                      | 不进入 A 线首批输入            |
| 仅因“未来也许会统一”而想重排公开入口                      | 视为越界，回到 B 线讨论          |

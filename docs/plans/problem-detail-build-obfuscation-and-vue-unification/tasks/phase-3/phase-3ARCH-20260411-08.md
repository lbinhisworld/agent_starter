# ARCH-20260411-08 · 定义 B 线 cutover readiness gate

## 1. 任务元数据

- 任务编号：`ARCH-20260411-08`
- Phase：`3`
- owner：`architect owner`
- 优先级：`P0`
- 状态：`completed`

## 2. 任务目标

- 定义 B 线是否允许进入切换的 go/no-go 门。
- 把切换前必须满足的合同与证据写成明确 gate。
- 避免 B 线在准备不足时进入灰度或切流。

## 3. 当前事实

- B 线切换依赖 A 线稳定、host 合同完成、后端 online-only 合同冻结、同 URL 技术切换合同冻结，以及 fixture/对照通过。
- 若没有 readiness gate，灰度切换很容易在边界不清时提前开始。
- readiness gate 是 A 线稳定与 B 线切换之间的最后收口层。

## 4. In Scope

- cutover readiness gate
- go/no-go 前提条件
- 与 fixture、host、后端 online-only 合同、同 URL 技术切换合同、A 线稳定性的衔接

## 5. Out Of Scope

- 具体灰度执行动作
- 切回模板细节
- 第二批范围规划

## 6. 前置依赖

- `FE-20260411-21`
- `FE-20260411-16`
- `BE-20260411-01`

## 7. 实施说明

1. 把 A 线稳定、host 合同落地、后端 online-only 合同落地、同 URL 技术切换合同落地、fixture / selector / DOM / 双渲染对照通过列为切换前置门。
2. 区分“未就绪”“允许继续准备”“允许真实灰度”的不同状态。
3. 明确 go/no-go 判定所需证据与责任人。
4. 让后续灰度与回退规则都建立在 readiness gate 通过之后。

### 7.1 readiness 状态定义

| 状态 | 固定解释 | 是否允许灰度 |
| --- | --- | --- |
| `not_ready` | 任一 P0 合同或验证证据缺失，或仍存在明确阻塞项 | 否 |
| `ready_for_preparation` | 文档合同已齐，但验证证据、运行时证据或灰度责任位尚未补齐 | 否 |
| `ready_for_gray` | A 线稳定、B 线合同齐备、双渲染验证通过、同 URL/fallback 有证据、责任人与切回记录模板已具备 | 是 |

| gate | 必须满足的条件 | 最低证据 | owner |
| --- | --- | --- | --- |
| G1 · A 线稳定 | `ARCH-20260411-06`、`FE-20260411-08`、`FE-20260411-09`、`FE-20260411-10`、`FE-20260411-11` 对应 deploy / smoke / 回滚 / 运行时证据链完整，且最新一轮 A 线 smoke 无 P0 未决项 | deploy 证据、smoke 记录、失败分级与验收记录 | frontend + architect |
| G2 · host / 首批范围稳定 | `FE-20260411-13`、`FE-20260411-15` 已落地为唯一合同，首批范围与 legacy island 边界未漂移 | host 合同、首批范围清单、无越界变更记录 | frontend |

### 7.3 直接 No-Go 条件

1. 任一 P0 fixture 的 selector 或 DOM 对照仍存在未解释差异。
2. 同 URL fallback 无法在当前 `index.html?caseId=` 下即时回到 legacy。
3. A 线 smoke 仍存在 P0 失败，或 `frontend/dist` 发布证据无法覆盖默认入口 / 登录 / 模型配置 / 详情往返链。
4. 后端 online 合同对 401 / 404 / 428 / `AI_CONFIG_REQUIRED` / owner isolation 仍有口径漂移。
5. 灰度与切回记录位尚未准备好，却试图进入真实切换。

### 7.4 readiness 判定表述模板

| 字段 | 固定要求 |
| --- | --- |
| 版本 / 批次 | 必填 |
| readiness 结论 | `not_ready` / `ready_for_preparation` / `ready_for_gray` |
| 未通过 gate | 列出 G1-G6 中未满足项 |
| 已通过 gate | 列出 G1-G6 中已满足项 |
| 阻塞项 | 只写当前真正阻塞灰度的事项 |
| 下一动作 | `补证据` / `修复` / `进入灰度` / `升级人工` |

## 9. 验收边界

### 9.1 完成结果

- 已明确 B 线切换必须以前置的 A 线稳定、host 合同落地、后端 online-only 合同落地、同 URL 技术切换合同落地、fixture/对照通过为条件。
- 存在可执行的 go/no-go 门，而不是靠主观感觉决定。

### 9.2 不算完成的情况

- 没有前置门或条件过于模糊。
- readiness gate 未绑定 fixture / host / 后端 online-only / 同 URL 技术切换 / A 线稳定性证据。
- 仍允许在关键合同未完成时进入灰度。
- 没有把未就绪、可继续准备、允许灰度三种状态分开。

## 10. 必备证据

- 文档或产物文件：readiness gate、go/no-go 条件表
- 命令或检查入口：`rg -n "cutover|go/no-go|A 线稳定|fixture|host 合同|BE-20260411-01|bootstrap|flag" docs/plans/problem-detail-build-obfuscation-and-vue-unification`
- 最小回归项：能据此判断一个版本是否仍停留在“不可切换”状态
- 若适用则写 diff / fixture / 运行时证据：切换前提检查表

## 11. 失败/停止条件

- readiness gate 与首批接管范围冲突。
- 切换判定无法落到固定证据上。
- A 线尚未稳定却被要求推进 B 线切换。

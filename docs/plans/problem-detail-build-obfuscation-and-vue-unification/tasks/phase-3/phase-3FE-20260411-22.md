# FE-20260411-22 · 定义 B 线灰度切换规则

## 1. 任务元数据

- 任务编号：`FE-20260411-22`
- Phase：`3`
- owner：`frontend`
- 优先级：`P0`
- 状态：`completed`

## 2. 任务目标

- 定义 B 线灰度切换的规则、责任人和判定口径。
- 明确什么情况下仍走 legacy，什么情况下允许切到 Vue shell。
- 基于 `FE-20260411-16` 已冻结的同 URL 技术切换合同定义灰度规则，不再另起一套 bootstrap / flag / fallback 口径，也不补充新的技术字段定义。
- 让切换路径可执行、可解释、可回退。

## 3. 当前事实

- readiness gate 通过后，并不代表可以无条件全量切换。
- 若灰度规则不清，现场很容易出现“谁来判定”和“哪些 case 走哪条链路”的混乱。
- 同 URL 技术切换合同已在 `FE-20260411-16` 冻结；Phase 3 需要做的是基于该合同定义灰度策略，而不是重写技术口径；若出现新的技术切换细节需求，应回到 `FE-20260411-16` 收口。
- 首批只接管壳层，灰度切换规则必须与首批范围一致。

## 4. In Scope

- 灰度切换规则
- legacy / Vue shell 的选择条件
- 基于既有同 URL 技术切换合同的灰度策略与使用规则
- 判定责任人与记录口径

## 5. Out Of Scope

- 切回模板细节
- 真实切换代码实现
- 全量 cutover 之后的长期治理

## 6. 前置依赖

- `ARCH-20260411-08`
- `FE-20260411-16`
- `BE-20260411-01`

## 7. 实施说明

1. 定义灰度阶段哪些场景仍保持 legacy，哪些允许切到 Vue shell。
2. 明确判定依据必须建立在 readiness gate 已通过的前提上。
3. 引用 `FE-20260411-16` 已冻结的同 URL 技术切换合同，把 bootstrap / flag / fallback 转译为灰度使用规则、责任分工与验收口径，不再另起一套定义，也不新增第二份技术合同。
4. 指定切换判定责任人和记录方式，避免现场口头决策。
5. 灰度规则必须与首批接管范围、online-only 边界、后端访问合同和同 URL 技术切换合同保持一致。

### 7.1 灰度前提

| 项 | 固定口径 |
| --- | --- |
| readiness 前提 | 只有 `ARCH-20260411-08` 结论达到 `ready_for_gray`，才允许进入本卡灰度流程 |
| 技术合同来源 | 只引用 `FE-20260411-16` 的 `?pdShell=`、`APP_CONFIG.PROBLEM_DETAIL_SHELL`、default `legacy` 三层选择规则 |
| 场景边界 | 只面向 online-only、首批接管范围内的壳层 / 步骤条 / 历史侧栏 / loading-error-empty |
| 禁止项 | 不得借灰度之名把主工作区、聊天链或高编排 task 内核一起切到 Vue |

### 7.2 灰度阶段划分

| 阶段 | 允许方式 | 默认流量 | 允许对象 | 升级条件 |
| --- | --- | --- | --- | --- |
| L0 | `APP_CONFIG.PROBLEM_DETAIL_SHELL=legacy` | 全量 legacy | 所有人 | readiness 未通过或灰度被叫停时维持 |
| L1 | 保持默认 legacy，仅允许受控使用 `?pdShell=vue` | 默认 legacy | owner 指定的验证人、指定 case、指定 fixture 对照场景 | 9 张 P0 fixture 双渲染记录齐、无 P0 差异 |
| L2 | 指定环境 / 指定批次把 `APP_CONFIG.PROBLEM_DETAIL_SHELL` 切到 `vue` | 受控灰度 | 经 architect owner 批准的验证批次 | L1 通过，且切回模板与残余风险模板已启用 |
| L3 | 继续扩大 `APP_CONFIG.PROBLEM_DETAIL_SHELL=vue` 的批次 | 扩大灰度 | 仍受批次控制，不等于全量切换 | L2 运行稳定、无新增 P0 / P1 阻塞 |

### 7.3 legacy / Vue shell 选择规则

| 情况 | 选择结果 | 说明 |
| --- | --- | --- |
| readiness 未达到 `ready_for_gray` | `legacy` | 禁止现场手动越权切到 Vue 作为正式灰度 |
| readiness 已通过，但未进入灰度批次 | `legacy` | 仅允许受控 `?pdShell=vue` 验证 |
| readiness 已通过，处于 L1 受控验证 | `legacy` 为默认；`?pdShell=vue` 仅供验证人使用 | 用于最小范围验证，不传播给普通用户 |
| readiness 已通过，处于 L2/L3 灰度批次 | 以 `APP_CONFIG.PROBLEM_DETAIL_SHELL` 为准 | 仍保留 `?pdShell=legacy` 应急切回能力 |

### 7.4 判定责任位

| 角色 | 责任 |
| --- | --- |
| frontend owner | 确认同 URL 切换、DOM/selector 差异、fallback 证据与灰度记录 |
| architect owner | 负责是否从 L0/L1 升到 L2/L3 的 go/no-go 判定 |
| backend owner | 对 online 访问合同、401/404/428/AI gate 漂移负责会签 |

### 7.5 灰度记录最小字段

| 字段 | 固定要求 |
| --- | --- |
| 批次 | `L1` / `L2` / `L3` |
| shell 选择依据 | `?pdShell=` 或 `APP_CONFIG.PROBLEM_DETAIL_SHELL` |
| 覆盖对象 | 指定人 / 指定 case / 指定环境 |
| readiness 结论引用 | 必填，回链 `ARCH-20260411-08` 结论 |
| 结果 | `continue` / `hold` / `rollback` |
| 残余风险 | 必填，若无写 `none` |

### 7.6 直接停止灰度条件

1. 出现任何 P0 selector / DOM 差异。
2. 同 URL fallback 无法即时回到 legacy。
3. 后端 online 合同出现 401 / 404 / 428 / `AI_CONFIG_REQUIRED` 漂移。
4. 首批范围外的区域被实际切到 Vue shell。

### 7.7 与 `FE-20260411-16` 的关系

1. 本卡只规定“什么时候允许用 `?pdShell=` / `APP_CONFIG.PROBLEM_DETAIL_SHELL`”，不重新定义这些键。
2. 若灰度期发现新的 bootstrap / flag / fallback 技术问题，必须回写 `FE-20260411-16`，而不是在本卡补第二套技术合同。

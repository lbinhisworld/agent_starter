## 约束

- 不加载 `frontend/main.js`；鉴权与 `tool-experience` 同属业务门禁页（见 `auth-runtime.js`）。
- HTML 壳须加载 `storage-http-adapter` / `storage-indexeddb-adapter` / `storage.js`（与 `home.html` 同源链），并在 `api.js` 之后加载 **`../frontend/js/task1BusinessInsight.js`**（提供 `extractDesignDetailBusinessInfoFromUserFeedback` / `extractDesignDetailCustomerRequirementFromUserFeedback` / `buildTask1LlmQueryMessage` / `generateDesignDetailBmcFromContext` / **`summarizeDesignDetailRequirementMergeByLlm`**（多轮需求合并；`taskTag: design-detail-req-merge`，审计由 `SmartCto.designDetailLlmLogContext`）等），否则设计页无法在 task1 执行经营信息提炼、客户需求提炼或后续 BMC 写回聊天。
- **`communication-history.js`**（在 `utils.js` 之后、`auth-runtime.js` 之前）：为「重启当前」聊天截断提供 `window.inferTaskIdFromMessage`，与 `main.js` `filterChatMessagesRemoveTask` 归属判定一致。
- **已知限制**：设计页 task1 启动自动确认写入 **设计页专用** 系统引导（`DESIGN_DETAIL_TASK1_GUIDE_CONTENT`），与案例详情页聊天内历史「请提供企业基本工商信息」可能并存于同一 case，属预期；未执行 `main.js` 内 item 侧合并；工商卡 **确认** 与初步需求提炼完整闭环仍以**案例详情页**聊天为准；**尾随未确认** `basicInfoCard`（及紧邻「工商信息提炼」或 **「设计详情经营信息提炼」** `task1LlmQueryBlock`）在本页再次发送成功门内会被 **`pruneTrailingUnconfirmedBasicInfoForDesignResubmit`** 自动摘除，不要求用户先去详情点确认。
- 构建产物：`frontend/vue-auth-assets/design-detail.js` / `design-detail.css`（及可能拆出的 `shared-problem-case-api.js`），入口 `frontend/design-detail.html`。

# Folder: frontend/js/core

## 地位

`frontend/main.js` 拆分过程中承接 **online 案例 API** 与 **应用状态 façade**、**聊天消息模型与渲染**、**壳层 DOM 与 helper**、**详情顶栏/步骤条渲染** 等可独立测试的模块，与 `main.js` 的 bridge 配合。

## 职责

1. 集中 `GET/POST /problem-cases/...` 等与案例包、任务动作、bundle 刷新委托相关的请求实现（零契约漂移）。
2. Phase 1B：集中详情页/聊天相关的**状态槽位**（当前详情项、详情聊天数组、首页 `chatHistory`）、**hydration 判定**（与 `__STORAGE_*_HYDRATED` 对齐）、**canonical 任务 id**（委托 `getFirstUncompletedTask`）；不包含业务编排规则。
3. Phase 2A：集中 DOM 元素缓存 `el`、壳层元素查询、基础 UI helper（`setHidden`、`toggleClass`）等；离开 `main.js`，无业务逻辑迁入。
4. Phase 2B：集中详情顶栏/步骤条等纯展示 UI 更新。
5. Phase 2B：集中详情区事件绑定与点击转发；业务仍在 `main.js` 命名处理函数，`main.js` 仅负责事件分发。
6. **Phase 3A**：集中聊天消息模型（push/save 辅助）、持久化入口（storage key 获取）、渲染辅助函数（setup* toggle helpers）及滚动辅助；`renderProblemDetailChatFromStorage` 宿主仍留在 `main.js`。
7. **Phase 3B**：详情工作区宿主 `renderProblemDetailContent`、`handleProblemDetailChatSend` 与 hydration 后 `ensure*` 管道（`applyStoredChatPostHydrationPipeline`）在 `problem-detail-runtime.js`；`main.js` 末尾 `initProblemDetailRuntime` 注入 `__host`，无业务语义分叉。
8. **Phase 4A**：`task2-companion-runtime.js` 承接 task2 BMC 生成、讨论/重生成编排（`SmartCto.task2Runtime`，`main.js` 注入 deps）；`task8-global-itgap.js` 承接全局 ITGap 四阶段与主站/报告同源渲染（`SmartCto.task8GlobalItGap`，**禁止**引用 task9 `localItGap.js`）。
9. **Phase 4B（续）**：独立「角色与权限模型推演」`task10-companion-runtime.js` 与独立「核心业务对象推演」`task11-companion-runtime.js` **均已移除**；CBO/RB 相关会话合并、审计占位与聊天块 dataset 由 `main.js` 内联；严格提示词与上下文构建仍在 `coreBusinessObject.js`（仅库函数，无 companion 编排）。

## 约束

- 不得修改 API path、method、payload/response 语义；不得新增裸 `window.xxx = fn`（仅允许 `SmartCto.*` 挂载）。
- 不得改动 storage key、hydration 事件名、状态字段语义；`app-state` 仅 façade，不吸收业务规则。
- 不得改动 selector、壳层 DOM 结构、交互顺序；`app-dom` 仅壳层查询与基础 helper。
- 不得改动 message type/payload、聊天块 HTML 结构；零语义漂移原则。
- Phase 3B 起：工作区宿主与发送编排由 `problem-detail-runtime.js` 承担；runtime 内禁止裸读 `window`（依赖 `__host` 注入）。
